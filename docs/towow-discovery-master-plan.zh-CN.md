# J++ × 通爻：通用发现能力总计划

2026-09-21。状态：设计与实施计划；不表示下面的机制或验收已经完成。基于用户持续讨论、通爻原始问题定义与实验材料，以及公开主分支 `0e76955` 的实现快照。本文是当前发现任务的统一入口，接续并调整此前的局部路线；历史结果保留。

**现在可以并行推进。语言团队建设唯一的 J++ 内核；发现任务建设用 J++ 表达的发现方法与评估。双方通过最小程序、输入输出和固定观察对接。不能把语言完成作为实验设计的前置条件，也不能把实验应用替代语言建设。**

**2026-09-21补充：本任务必须交付两项建设成果——通爻可用的发现组件，以及从实际构造过程中提炼并落实的 J++ 改进，使复杂算法更容易构造。检验现有语言是否好用是第一步；仅提交评价或缺口报告，不算完成第二项。** 用户的原始构思作为设计输入保留，具体改进需要指回这些构思和实际编程证据。

## 1. 我们到底在建设什么

| 层次 | 要交付的东西 | 本任务如何参与 |
|---|---|---|
| J++ 通用语言 | 值、问题、方法、组合、未决与续接的语义，以及 Rust 执行系统 | 从实际算法提炼并交付可复用方法、接口或工具改进；需要内核支持的由唯一内核统一落地，不止报告缺口 |
| 通爻协议与发现前端 | 异质主体如何交换发现信号、局部判断、转介、披露和候选组合 | 继承已有契约与网络参考实现，比较其中可替换的发现机制 |
| 用 J++ 编写的发现方法 | 局部上下文如何产生问题、关系候选和下一步计算；中间结果如何影响发现 | 这是本任务主要实现对象，最终以源程序、可调用组件和评估结果交付 |
| 演示与论文式说明 | 让别人看懂、运行并复用上面的方法 | 跟随实际结果更新，不以页面、故事数量或测试数量代替能力验收 |

语言目标是让作者用少量规则构造设计者未预置的算法。发现目标是让模糊信号与不同局部世界相遇，产生发送者没有命名的有价值关系。两者互相提供需求和验证场景，但不是同一个完成条件。完整通爻还包含协商、关系形成和现实执行；本轮交付到可继续协商的候选与交接接口。

### 语言能力与算法共同构造

不预设“先用成熟工具完成整个算法，再让J++逐步接管”。所需的构造工具可能正是语言工作要创造的部分：新的表达、组合与执行能力，可以使原本难以组织或在可承担成本内难以运行的方法成为实际可构造的程序。现成完整算法不是语言设计的前置条件；已有工具与参考实现按实际需要复用。

从目标所要求的计算关系出发，将缺少的J++能力与最小算法片段一起设计、实现和验证。当前能表达的部分直接写源码；尚不能表达的部分先用明确标记的设计记号说明规则，再落实到唯一内核或公共方法。不能因当前语言不趁手而收缩问题，也不以新增抽象数量作为成果。这里主张的是构造能力与算法共同发展，不宣称其他通用计算体系在理论上不能表达它。

本次补记只沉淀理解并修正推进前提，没有启动新的实现或模型实验。两项交付要求与既有P0～P5继续保留；下次恢复时，先明确最关键的一段计算关系需要什么语言能力，而非先要求一份完整宿主算法。

## 2. 问题定义与输出

网络中的主体互不完全了解，每个主体持有丰富、持续变化的本地上下文。发送者可以只给出模糊材料，不能被要求先列清问题、合作角色或目标人。接收方结合自己的世界提出可能的直接关系、多人组合或转介；正在进行的计算与中间组合又能成为后续计算的输入，并改变之后更值得探索的方向。

长期目标是在很大且动态变化的网络中，在可承担的计算、通信和维护成本内，持续增加值得深入互动的机会。这里的“发现”主要负责不漏掉机会；误唤醒按消耗资源计价，关系是否成立留给后续核对与协商。程序可以返回有用的部分结果，无需等全部未知消失。

一轮输出至少包括：候选成员或转介路径、可能共同完成什么、触发它的本地事实和判断、还缺的材料或条件、下一步可执行的查询或交接。关系读数带着题面、尺度、版本与来源；不能把不同问题的数字直接相加成一个全网分数。

### 最小形式化对象

把一次实验定义成一个发现过程：初始信号、各主体本地世界、可见拓扑、允许披露的信息、随时间到达的变化、资源预算与调用者的结果需求。被测方法只取得当步允许看到的局部材料，产生提名及后续计算；评估器另持标签或事后核对结果。全量世界可用于信息上限基线，但不能偷偷给局部方法。

以下是设计记号，不是新文法或强制协议字段：

```text
C_i(v)      主体 i 的版本化本地上下文
W_i(t)      它正在进行的计算、问题与可暴露的中间结果
S_i(t)      P_i(C_i(v), W_i(t), 已收到的关系信号)
N, Q, D    G_i(收到的材料, C_i(v), 当前可见的其他结果)
下一批计算 R(当前信号, N, Q, 已披露材料, 剩余预算)
新状态      U(本轮观察, N, Q, D, 新事件)
```

`N` 是候选关系/组合/转介，`Q` 是下一问，`D` 是披露或交接请求。`P/G/R/U` 都是可替换方法；JEV可参与其中的判断，生成与精确算法承担各自部分。相同接口不要求相同题目，也不要求所有节点用同一个模型。下一轮可以新增、修订、拆分或撤回候选；不把“组合”永久限制为只增加成员。

调用者提供本轮何时已足够、何时需要继续的要求。返回值包含已有可用候选和仍未解决的部分，而不把“模型很确信”或“预算用完”统一叫作任务完成。

有三类结果必须分别记：找到原有但未知的路径；通过互动形成新的合作假设；实际改变条件并形成可执行的合作。第三类还需要目标侧行动与参与者反馈，不能由前两类的候选报告代替。测试同时保留原始意图，检查是否靠偷偷缩小目标得到“成功”。

### 对核心构思的推导

1. 如果有价值的联系依赖接收方上下文，发送者事先列出的类别不够；接收方需要能够构造问题、提名或转介方法。
2. 如果多人合起来才提供能力，逐人排序不是充分表示；组合需要保留成员、分工、约束、依据和未决项，并能再次参与计算。
3. 如果进行中的计算也有价值，系统不能只发布终局画像；需要按版本暴露可复用的中间结果或变化事件。
4. 如果这些结果能指导下一步，路由、提问和局部表示应可由程序更新；静态检索是可用基线，不是完整闭环。
5. 如果规模很大，收益必须来自有选择的唤醒、复用、聚合与维护；单次 JEV 判断便宜不会自动消除全网扫描、组合枚举和材料读取的成本。
6. 因此，J++ 的价值应体现在“能表达并替换整段发现计算”，通爻方法的价值应体现在“这些计算实际增加了发现机会或降低了总成本”。分别测量，不能互相代证。

**具体准备步骤：**先用元数据盘点已有完整案例和评判覆盖；按同一作者、项目、事件及重述材料分组，整体分入开发集或评估集，不能随机拆候选边。已被此前调参使用的案例继续归开发侧。新标签、未知标签、分歧标签与自然负例分别存放。盲测只登记数量和规则，保持内容隔离。

真实来源文本保留出处与时间，轻度匿名化之外的改写明确标成构造材料。主体本地事实、可传播信号、按需披露内容和仅供评阅的答案分开提供。方法不能先看完整世界再声称只用了轻量信号；中心基线若获得更多信息，单列为信息上限参考。

不重启旧的整批 23,596 项金标生产。先从少量完整开发案例验证题目、判据与执行可靠性，复用可确认的有效评判，补当前比较真正缺的部分。正式验收集大小由独立案例数、预期差异和试运行方差决定；10～15 个分层开发案例只用于机制调试，不足以宣称提升。

候选全集有足够完整标签时才算 Recall@k。新组合可能不在旧答案表中：把各方法输出的并集去掉方法身份后独立评阅，并补抽未输出候选；不把“旧表没有”判成错，也不把“模型觉得可行”判成真实成功。不完整标注下报告已知正例覆盖、评阅候选产出和覆盖缺口，不报告总体准确率。

每个开发案例包只需包含原始信号、接收方局部事实与出处引用、各步可见范围、允许的变化事件、预算及验收条件；答案和事后事实由评估侧另存。正式候选评阅采用两次相互独立、看不到方法身份的判断，评阅者不参与该方法的构造或调参；分歧保留并核对具体事实，抽样人工复查。模型一致仍只是候选可行性的评判，现实意愿与采纳另测。

## 5. 需要比较的机制，而不是先指定胜者

| 方法族 | 它回答的问题 |
|---|---|
| 强检索与规则基线 | 现有 BM25、稠密/混合检索、固定能力描述和相对排序在什么片段已经够用？ |
| 中心强模型基线 | 相同可披露信息与预算下，一次集中推理能完成多少？如果增加信息或费用，得到多大的上限参考？ |
| 接收方局部提名 | 收到材料后，接收方依自己的世界形成待检验的问题、贡献或转介；能否补出前两类遗漏的机会？ |
| 组合与继续发现 | 将已有候选作为材料交给下一方，能否形成逐人判断没有得到的可行组合？ |
| 中间结果影响后续路由 | 使用进行中的问题、读数与组合更新发现信号，相比冻结信号或只更新终局结果，发现延迟和成本如何？ |

先比较不同机制，再调各自参数。沿用已有方法实现，避免把弱化的旧系统当靶子；历史数据缺少可复现模型或费用时，将“旧记录对照”和“当前同条件重跑”分开列。

接收方方法的首版可以由生成模型根据其局部事实生成题面、提名和披露请求，再交 JEV 判断与精确代码处理约束；也可以从局部已有方法组合。**开放的语义内容与有限的通信动作并不冲突。** 不需要先实现任意代码自修改。生成器、JEV、检索器、求解器各自的成本和版本都进入记录。

为了区分语言与算法的收益，选定同一算法、同一输入和观察，再比较直接宿主实现与 `.jpp` 实现：输出、必要效应与未决项应一致，分别记录改策略时修改哪些文件、复制多少公共逻辑及独立作者是否能扩展。不能用一次开发快慢或代码行数单独推导普遍十倍收益。

### 5.1 从应用回到语言：必须完成的建设循环

第一步使用已有J++解决问题并识别实际难点；第二步产出“怎样让此类算法更容易构造”的具体答案并实现它。具体答案可以是能组合的方法库、语义清楚的接口、减少重复组装的源码表达、诊断或执行优化。能够在库与工具中解决时，不为了凑语言贡献增加内核原语。

原始构思给出了更具体的建设方向：**选什么材料、问什么问题、怎样根据结果继续，这三件事本身都应可编程、可替换、可组合，并能递归使用已有方法。** 例如，选择“有助于下一次判断”的材料，本身就可以调用判断方法；决定本次需要哪些问题，也可以成为一个方法的结果。不能把它缩成固定分块、固定谓词表或只支持是非题的流程模板。接收方发现是这套构造能力的一个用例，跨领域材料选择、自适应选题和约束搜索都可检验其复用。

每个重要改进保留同一条链：**用户原始构思 → 一个确切的构造困难 → 使用或缺少的J++能力 → 可运行的改进 → 另一个算法复用 → 发布后的用法与前后差异。** 构造困难可以在算法尚未完整实现时出现；先写清所需的计算关系，联合设计缺失能力与最小片段，再提炼共同结构。若一种压缩写法抹掉观察、未决或副作用的差别，就不算更好的抽象。没有完整旧程序时，前后对照记录原来的表达阻碍与新程序如何消除它，不编造一个旧完整实现。

| 循环步骤 | 必须留下的结果 | 随哪项工作推进 |
|---|---|---|
| L0 能力使用记录 | 实际源程序、所用J++机制、宿主算法与外部模型各自承担什么 | P0/P1，先记录当前基线 |
| L1 构造困难定位 | 一个必须反复写、难替换、难继续组合或缺少表达能力的最小片段；明确原始意图 | P1/P2，来自具体构造尝试；不要求完整算法先存在 |
| L2 抽象与实现 | 一项可安装/导入/调用的共同方法、接口或工具改进；内核改动归语言主线 | 与P2/P3并行，不等应用全部结束 |
| L3 跨算法复用 | 同一改进用于结构不同的第二种算法；至少一例不依赖通爻职业或关系概念 | 复用现有自适应选问/约束构造样例，检验新改进实际减少了什么 |
| L4 开发者交付 | 新的完整程序与替换策略示例、独立作者使用结果、版本与说明；旧实现存在时给出完整对照，否则保留原构造阻碍 | P5；与发现组件一起交付 |

首个候选已经有具体依据：原生 `adaptive.jpp` 与 `partial.jpp` 各自重复写出 `observe/resolved/answer` 一组观察与出口处理方法；`partial.jpp` 的 `packet` 已把结果投影、剩余项和推进方法作为参数。这给出了“共同观察方法＋可替换续接构造器”的起点。下一轮需检验能否提炼成供其他程序直接使用的源码方法库，保留不同问题类型与未决含义。这是有源代码依据的候选，尚未实施，也不预先认定它是唯一答案。

### 5.2 具体使用了哪些J++能力

下面是本次核读快照，不把原生示例的能力写成发现应用已经迁移。后续每个运行包把最后一列换成实际 `.jpp` 位置和运行证据。

| 能力 | 当前代码依据 | 在发现算法中承担什么 | 当前应用状态 |
|---|---|---|---|
| 方法作参数/返回值，组合后再组合 | [`compose`](../rust/examples/composition.jpp)；Python参考中的 `DISCOVERY_METHOD` | 替换路由、提名和继续策略，复合方法继续被调用 | 原生示例与Python发现链各已存在；原生发现链待接 |
| 问题作值，前一结果决定下一题 | [`adaptive.jpp`](../rust/examples/adaptive.jpp) 的 `step/solve` | 接收方产生问题，依据结果决定补问 | 原生固定观察示例已有；发现案例仍用调用者预写题面 |
| 材料与语义观察分开 | [`partial.jpp`](../rust/examples/partial.jpp) 的 `mat/state/judge`；参考应用 `jv.transform/jv.judge` | 保存成员资料、组合依据与实际判断 | Python发现应用已用；Rust对应机制可用于迁移 |
| 显式未决与出口处理 | `cut/handle`，参考应用的 `_grade` | 未知保留为未知，让其他候选继续参与 | 两个实现都有对应路径；跨实现等价需按固定记录核对 |
| 纯计算与模型判断组合 | `map/filter/fold`、源码 `combinations/feasible` | 语义观察后用精确约束构造可行组合 | 原生示例已有；既有发现应用的检索和枚举仍有宿主代码 |
| 部分结果与可替换续接 | `packet/continuation`；参考应用 `nomination_as_input` | 交付够用结果，换策略继续；组合成为新输入 | 原生闭包续接与应用数据再输入是不同机制，不能相互冒充 |
| 预算、记录与重放 | [原生运行说明](../rust/README.md)；参考应用 `execute` | 明确何时调用与复用，比较冷启动和后续计算 | 固定程序重放已有；持续异步路由尚未接入 |

问题类型也要如实记录：当前Python发现参考使用度量与排序；原生自适应示例使用是非判断。本次尚未展示选择型问题在发现应用中的独立作用，后续应给出实际用途，而不是把所有读数压成布尔值或为凑类型加入无用步骤。

这里的组合算法、BM25、生成模型和网络传播并非因被调用就成为J++独有能力。语言贡献在于它们如何被表达、传递、替换和继续组合；模型质量、算法收益和编程便利分别举证。两个算法复用是首个交付门槛，不等于已经实现用户提出的广泛任务与机器类型通用性。

## 6. 验收合同

下面是拟采用的分层合同。行为条件可以直接检查；数值目标在开发轮后、看正式评估结果前登记。每层完成只声明该层完成，不以绿灯数量相加表示整个问题解决。

### A. 可编程与组合

- 发现流程的分支、选问、候选组合、停止及继续策略由 `.jpp` 源码表达；宿主只做通用 I/O、检索或模型能力调用。
- 同一组构件用于至少三种结构不同的任务：直接供需、经第三方转介、多人成组。更换角色和领域不修改语言内核。
- 一个未参与实现的作者，只看接口与例子写出第四种未预置策略；必须修改内核才能接入的地方记为表达缺口。
- 固定观察下，封装/展开和 Python 参考/Rust 源程序保留约定的结果、观察身份及未决项；合法批量优化不要求物理请求字节相同。
- 暂时不确定不阻塞其他可计算部分，续接不丢原始目标和旧依据。重复计算与重新观察在记录中可区分。
- **必须有已实现的构造改进。** 至少一项从实际困难提炼的共同方法、接口或工具进入交付；保留改进前/后程序，以两个不同结构的算法复用，独立作者能按文档接入。没有这项成果，即使发现案例有效，也只能声明发现侧完成。
- 对每项改进回答：具体使用哪些J++能力、原来作者要承担什么、现在由什么抽象承担、改一个策略还需要改哪里。代码变短只是辅助观察；不能把复杂度转移到未公开的宿主黑盒中。

### B. 发现行为

- 输入没有指定目标人或答案角色；至少分别覆盖显式、隐含、多方、转介、跨语言和困难负例。
- 接收方提名能指回本地事实；自动产生问题/方向与开发者预置方向分别标记，不能用后者通过前者验收。
- 转介中，主体本身不必能提供服务；验证其本地关系如何使另一个主体进入可见范围。
- 多人案例中，明确联合满足什么条件以及移除关键贡献后失去什么；不能把几位高分候选并排显示算作组合收益。
- 新中间结果在最终方案完成前确实改变下一步查询或可见路径；关闭这项反馈后，相应改变不应仍由隐藏的预写脚本发生。
- 条件不够时提出补问、披露请求或保留未决；不得通过降低输入目标、捏造成员事实或跳过关键约束完成案例。

### C. 效果与费用

主比较是**相同总预算下的已评阅有效机会覆盖**，另画达到相近覆盖所需的费用曲线。按任务与难度片段分别报告，不让容易的职业匹配掩盖转介或组合失败。

| 指标 | 测量方式 |
|---|---|
| 覆盖与遗漏 | 完整标签片段的 Recall@k；不完整片段单列已知正例覆盖与抽样审查漏失 |
| 有用提名 | 去重后有事实支撑、符合原始意图、值得继续核对的候选数量；与真实接受分开 |
| 错误方向与误唤醒 | 无助于需求或需后续排除的数量，以及实际浪费的调用/费用 |
| 发现时间 | 第一个有效候选的时间、p50/p95 延迟、更新后新机会被发现的延迟 |
| 全成本 | 建索引、局部算子生成、检索、JEV、生成模型、披露、通信、缓存维护、失败重试；冷启动/重复运行/持续更新分别记录 |
| 统计单位 | 按独立案例或更高层作者/项目组配对；共享资料的上千条候选不能冒充上千独立样本 |

建议的首轮实用目标有两种：同预算下困难片段的宏平均有效覆盖提高至少 5 个百分点；或者覆盖下降不超过 2 个百分点时，在线总推理费用至少减半。前者要求配对95%置信区间的改善下界高于0；后者要求覆盖非劣区间下界不低于−2个百分点，并报告节省比例的不确定性。两种目标都检查各片段得失及首次生成成本，不用平均数掩盖关键行为消失。

这些数值是**新计划的候选验收目标**，不是旧研究已有标准或用户承诺。开发阶段根据实际场景价值和统计功效决定是否采用、修订理由是什么；在正式测试前锁定。小样本区间过宽就报告不确定，不能为凑通过反复换测试集或事后降低门槛。

### D. 动态与规模

用同一份加入、退出、资料更新、关系失效和任务到达事件流，对照固定信号、只更新终局结果、使用中间结果三种策略；再比较全量刷新与按依赖更新。测试旧结果何时失效、哪些仍可复用，以及有用的新路径何时出现。暂时只保留有版本的中间快照也可以，不必等待分布式流系统。

规模轮从已有32～2048节点负载复用计数器，按结果逐步扩大。合成填充只用于负载，不作为发现质量证据。记录轻量比较、深推理、网络字节、初始化、单次更新、内存及累计总工作。只有深推理次线性、却在别处全量扫描时，不能称总成本已解耦。规模曲线同时报告图结构、连通性、冷启动和长尾探索条件；不从小图外推亿级保证。

NAC/跨编码器、聚合和截断属性只在实际采用该机制的阶段测试。旧 Gate 2 的跨编码器/同编码器 Recall@100 ≥ 80% 是 NAC 相关目标，不是所有发现方法都必须为之重建的一套前置工程。编码坐标或多节点分发本身不构成加密保证。

### E. 真实使用与公开交付

最终历史盲测保留事发前材料，避免把合作结果写入输入；记录哪些历史机会被提前提出及为什么漏失。这之后再用经参与者同意的真实任务观察提名被接受、拒绝或改写的过程。只有获得这些反馈才能报告采纳率；实际关系形成另看执行与目标侧效果。

交付物是可安装运行的 `.jpp` 方法、替换接口、受支持范围、数据使用说明、对照与失败案例、复算命令及可交互说明。页面显示真实记录，也提供运行入口；不能只交排行榜或动画。

语言建设循环L0～L4贯穿上述各步。P1/P2完成时至少带回实际能力使用表与具体构造困难；总任务完成时必须交付已经解决其中困难的复用成果，不以“后续建议语言团队改进”结项。

## 8. 与语言团队怎样协作

语言团队继续维护唯一 Rust 解析器、检查器、解释器和通用能力接口。发现任务维护实验资料契约、发现源程序、旧前端适配、比较与案例。规划与应用使用独立分支，保持正在开发的研究目录不变。

当前最小交接是：普通 JSON 输入进入源码值；材料/问题/模型/校准与观察身份的映射；通用模型或工具调用接口；结果和未决项输出。先用固定观察执行源程序。真实模型适配就绪后只替换观察提供方；仍需单独测模型质量。检索可作为通用宿主能力，但不能把整个“找人→组合→继续”的算法藏在 `discover()` 黑盒中。

截至本次快照，Rust内核有可选的HTTP判断客户端实现，但公开CLI仍只连接固定观察；生成与问人也没有完整可运行接线。运行轨迹不是网络事件订阅，账本重放也不直接承诺跨程序、跨版本缓存。这些属于明确的集成项，不应在计划里重复写成“还没有函数或组合能力”。

异步传输、跨机器状态和任意闭包持久化不是小规模闭环的前置条件。先用输入事件序列和有版本结果表达动态语义；如果缺少某个语言能力，提交最小程序、预期行为与当前阻碍，由内核统一处理，不另造 Python 正式内核或第二套调度语义。

同一批模型观察用于迁移对照，不因换 Rust 再支付同一批判断费用。无须每次上游改动都重新移植；在一个已发布提交上做完能力包，再集中更新依赖。对外分别记录语言完成、发现行为完成、效果评估、公开部署和现实采纳。

| 画像来自正在进行的计算，不只是历史结果 | P4专门比较中间结果、终局结果和固定信号；未完成但有依据的结果可以继续影响发现 |
| 得分有参照系，数字变而关系含义持续维护 | 问题/刻度/版本参与身份；NAC可作候选参照，不假定所有读数天然可比较 |
| 异步、缓存、分布式计算能让持续发现可承担 | 区分冷启动、稳态与更新成本；先验证事件语义，分布式和隐私保证另给机制依据 |
| 有“哇”的可用效果，而且避免只做包装 | 行为、质量、费用和独立作者能否写新方法分别验收；演示展示真实变化 |
| 分支展开、回来用原目标审阅，避免忘记规划 | 当前总计划作恢复入口；实施带回程序和对照；分支隔离不自动消除偏见 |
| 不止检验语言，要产出使复杂算法更容易构造的具体改进 | L0～L4贯穿发现开发，A类验收要求实装改进与跨算法复用；逐项记录用了什么语言能力 |
| 跨很多任务与机器类型，继续寻找让大胆构想成立的条件 | 旧原话集第39～40、52～60条；两个算法是首个门槛，保留更广泛的通用性方向；每次局限都对应下一项可构造、可检验的改进 |

其中“计算改变可发现性，可发现性改变后续计算”是当前需要贯彻的构造主张；表中的具体机制与验收是本次工程推导。关系质量、规模优势与语言表达收益由不同实验支持，不把用户提出的构想改写成已经证实的事实。
