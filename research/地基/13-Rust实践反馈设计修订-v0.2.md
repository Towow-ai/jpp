## 1. 方法的构造与调用分开

**实践来源：** 高阶方法检查曾把创建、存储或返回函数当成执行函数，导致合法纯函数误报（Rust 内核第三、四包）。

**规则：** 创建方法值本身不执行其函数体。创建过程中实际求值的表达式，仍按其真实效应计算。函数体的效应属于未来调用；方法可作为参数、记录成员、列表元素和返回值，位置变化不改变此规则。普通数据结构与函数为组合基础，不新增按位置特判的语言构造。

**验收：** 返回一个未来调用 judge 的方法，返回步骤不产生 judge 调用；随后调用该方法才发生 judge。把它存进记录也得到相同区分。

## 2. 效应属于方法契约，并在调用处实例化

**实践来源：** 旧函数类型丢失效应；单态并集把不同调用点混在一起；最新核心已推进 rank-1 效应推断，保留这些成果，不重复实现。

**规则：** 方法类型包含参数、结果、效应信息和必要的捕获责任信息。未标注的高阶方法可按参数方法的效应推断，并在各调用点实例化；不能把某次带 judge 的调用污染到另一次纯调用。显式效应集合是调用者可依赖的上界，不能因为某次实参恰为纯而悄悄缩小作者声明。`Fn(A) -> B` 兼容旧式未知效应；前端正在采用的 `Fn(A) -!{judge}-> B` 表达已知上界。效应变量的显式语法留待实际需求，不作为本版前置。

无法解析的效应明确保留“未知”，不当作纯，也不吞掉同时已经确定存在的效应。下界分析可以指出遗漏的已知效应，但不能为融合、重排或缓存提供完整证明。错误提示说明位置和已知缺项。

**验收：** 同一个 apply 分别接纯方法与 judge 方法，两个调用点得到相应效应；经记录、返回值、别名和递归传递的可支持路径保持含义。未知路径明确记录边界，不假称全静态保证。

## 3. 未决结果按实际去向传递

**实践来源：** 仅进入 unsure 分支就销账，会使 `unsure: false` 静默吞掉未决；分支出口修复尚不能自动覆盖闭包、容器、暂停。

**规则：** 替换 `12` 中“进入 match/handler 即 consumed”的执行解释。类型声明表达允许返回未决，实际返回值或后续计算承接它才构成转移；只读原因文本不构成处理。

合法去向继续包括：明确处理、交给其他判断/请求处理过程、显式 drop 并记录，或随返回值/继续方法交给调用者。向下转交后，后续新产生的未决仍受同样规则约束。`literalize` 表示走了重问路径，不证明新题一定更字面或答案正确；`escalate` 也不保证对方已回答。

列表、记录、方法捕获环境和 Pending 保存的恢复信息都不能让未决无声消失。按责任标识追踪别名，不能把重复引用当成多份独立证据。允许显式丢弃，不擅自把语言改成必须问人；约束针对未决义务，不要求所有值都使用线性类型。捕获未决的方法能否复制/重复调用，必须以责任转移规则明确处理，不能因一个布尔标记就声称完整线性系统已经建立。

**验收：** 未决可包在记录或继续方法中返回，再由调用者接续；取字段/过滤导致最后一份承接信息丢失时应显式处理或报错；暂停恢复仍能找到它。由实现者选最小可行表示，不要求立即实现跨进程闭包序列化。

**2026-09-23 注（B52）**：捕获未决的方法按可达性核归属，不按单值归属字段。程序返回前从返回值、各帧、闭包捕获环境出发，可达的未销账责任即 J-05。捕获未决责任的方法值记它捕获的责任标识集；只在它是某条责任的唯一可达路径时是 `Fn¹`：调用一次后责任按实际去向销账，之后再调用、复制或丢弃该闭包为运行期错 J-05。静态只对显式标注 `Fn¹` 的名字检查；不建完整线性类型系统。运行期记账加少量静态检查（总账 K-048）是本版强制点，局部线性判断形式（K-146）是静态面的目标形式，两者不冲突（总账冲突 #58 关闭）。理由：B17 的标准写法把捕获未决的闭包放进记录，同一批未决同时经 `pending` 字段、原契约值与闭包可达，「复制进容器即错」会拒掉它。替代与放弃：完整线性类型——放弃，与高阶多态共存困难且本版只有一样东西要线性；单值归属字段加复制即错——放弃，与 B17 冲突。推翻条件：若探针程序中合法的「同一续接方法调用两次」写法普遍存在，则提前做 `Fnω` 提升的静态推断。理解偏差与更正：修订前把「别名不构成两份证据」误推成「别名即错」；证据不重复计数与责任经多条路径可达是两件事。〔依 Nature 2026-09-23 授权，架构终审通过，裁定 B52（地基/20-架构方案-v1.md 附录 A）〕〔B134（2026-09-25，步 21 实现口径）：Fn¹ 只在创建责任的帧返回时判定，责任属调用者帧时不标（唯一性证不了，不收紧；二次处置责任不是错放不可逆 `do`）；「复制」读作「经任何别名的第二次调用」，绑定与容器构造处不拦；闭包创建时遍历环境的代价属实现，改为返回时算不改语义。推翻条件：探针出现调用者帧责任经闭包被处置两次且产生两次 `ask`，则帧保存环境、判定时扫活帧。依 Nature 2026-09-23 授权，Fable 裁定 B134（地基/附注/2026-09-25-库层出口合成与待补批3裁定.md §四）〕

**2026-09-23 注**：组合封闭性契约（`12` §2.12）的第二条不变量「未决责任随包转移」由本节规则强制。〔依 Nature 2026-09-23 授权，Fable 裁定 B17（地基/附注/2026-09-23-决策单B栏-Fable技术裁定.md）；六项见该文件 B17 条与 §三〕

## 4. 方法身份包括实际捕获状态

**实践来源：** PR #12 审查指出闭包只按正文哈希，transform 会错误复用不同捕获值的方法结果。

**规则：** 运行时方法表示为代码与词法环境；用于可复用结果的身份不能仅取代码正文。捕获的语义相关值、实现/渲染版本以及既有输入身份必须参与对应复用条件。不能以地址或进程内临时编号冒充可跨运行稳定的身份。

若某个捕获环境无法可靠指纹化，禁用该项跨运行缓存或明确报告不支持；不返回另一方法的结果。正常方法调用仍可执行。一次运行的执行记录与跨程序缓存分开：记录完成事件不等于证明任意未来调用都可复用。递归环境的具体编码由核心实现解决，不能无限展开。

**验收：** 工厂返回正文相同而捕获值不同的方法，对同一输入产生各自正确结果；相同程序按已有记录重放不发生新的外部调用。

**2026-09-23 注**：跨程序复用的变换键只由本节的方法身份与输入决定，不含调用位置（`12` §2.10 注，已定未造）。〔依 Nature 2026-09-23 授权，Fable 裁定 B20（地基/附注/2026-09-23-决策单B栏-Fable技术裁定.md）；六项见该文件 B20 条与 §三〕

## 5. 调用前预算与调用后事实记账分开

**实践来源：** PR #12 审查指出已完成调用的实际费用超剩余预算时，旧顺序先退出，丢掉费用和结果。

**规则：** 调用前根据已知信息核预算；后端返回后，先记录实际完成的请求身份、结果与实际费用，再决定是否允许下一步。超预算可以停止后续计算，不能抹去已发生的调用。恢复时复用已完成记录，不能因上次超预算自动重复付费。

请求超时且无法知道远端是否完成，与已经拿到结果是两种状态；标明未知，不承诺普遍的外部 exactly-once。按适配器已有的幂等或核对能力处理，不为本版新建通用分布式事务系统。

**2026-09-23 注（B55）**：不可逆 `do` 发出前写意向条目，返回后写效应条目，两条都逐行落盘（账本是追加日志，意向与不可逆效应逐行同步落盘，其余条目层末批量）。续接时有意向无效应的不可逆动作不重执行，产出 `Fail(UnknownOutcome)` 走 `Unsure(fail)`；可逆或画像声明 `idempotent` 的动作重执行；续接只执行没有意向条目的动作。理由：整份文件原子写的账本满足不了「意向先落盘」，每次追加整份重写是 O(n²)，只在结束时写则崩溃后意向不存在；恢复只以账本为准（`12` §2.6）。替代与放弃：不记意向、续接一律重执行（现状）——放弃，不可逆动作可能重做；一律不重执行——放弃，可逆动作没必要留未知；整份 JSON 原子写——放弃，理由如上。推翻条件：若某类执行器提供幂等键使重执行安全，该动作画像声明 `idempotent: true` 时可重执行。〔依 Nature 2026-09-23 授权，架构终审通过，裁定 B55（地基/20-架构方案-v1.md 附录 A）〕

**2026-09-24 注（B83）**：续接一趟只用一套校准线——续接那一趟的校准视图。已完成的读数复用、不再付费（本节规则），但出口在续接趟按本趟的线重新切；首跑命中的键在库里换了线，续接报 `W-header: calib_used_hash` 并列出变化的键，不拒绝续接，账本头行的 `calib_used` 改写为续接趟实际命中的记录集合，之后只凭这份账本重放复现续接趟。不做「已命中键钉旧线、新键用新线」：库把一条线停岗或换线后，钉旧线会让续接趟继续用库已不认的线放行不可逆 `do`。〔依 Nature 2026-09-23 授权，Fable 裁定 B83（地基/附注/2026-09-24-B83续接缺口裁定.md）〕

推测执行、批处理与重排同样服从这些语义。保留已有融合/调度设计，但额外模型求值并非无条件零成本；优化须说明依赖、后端条件和允许的成本变化，不能悄悄执行未选中的外部动作。

**验收：** 用本地替身返回高于预估的费用：结果、费用被保存，程序停止新增调用；带该记录恢复不会再次请求。验证此规则不需要付费实验。

## 6. 整数行为不随 Rust 构建模式改变

**实践来源：** PR #12 审查指出 Int 溢出可能在 debug 崩溃、release 回绕。

**规则：** 本版沿用现有有符号 64 位 Int 范围。算术溢出、除零及相关边界返回指向 J++ 源码的运行错误；不以 Rust panic 或隐式回绕表达正常语言行为。需要将来支持大整数时另行扩展，不用本轮顺便改变数值系统。

**验收：** 最大整数加一、最小整数取负及除以负一、除零等相应路径在调试和优化构建下遵守同一规则。

## 修订与交付方式

以上规则是同一版本的局部优化，不要求新一轮整体架构评审。实现状态应以当前代码核对：已经成立的保留，尚缺的补齐。已有正常程序必须继续能表达，不能只用拒绝更多程序的方式通过测试。设计验收采用上面的具体行为，不以测试数量替代。

五步版本计划继续执行：源码运行 → 方法与结果组合 → 外部能力与运行生命周期 → 程序库与基础优化 → 整版交付。必要正确性修复随相关模块完成；新题式、全部优化、所有模型迁移和所有长期探索不自动成为当前版本门槛。

公开同步以实际版本区分“设计规则／实现状态／验证结果”。本文包含设计决定和引用的实践发现，不代表本轮已运行所有验收或复现每条 PR 审查。

> **附注（总控提议，2026-09-21 01:30，待 Nature 认）：补一条规则候选「恢复由账本决定，不由运行时续延决定」。** 来源：OCaml 探索（`附注/2026-09-21-OCaml探索-三个类型系统需求.md`）的防御性发现。Pending 与续解在语义上是分隔延续；OCaml 5 原生给 one-shot 分隔延续，Rust 稳定版的 `async` 也是现成的 one-shot 续延。**两者都不可序列化**，因此都不能承担跨进程恢复。风险在于：将来若有人为省掉重放的墙钟时间做一个进程内 resume，「恢复后那一半」的控制流就来自内存里的续延而不是来自账本，**J-18（账本头不同即不承诺重放一致）会在没人注意时失效，账本从审计物退化成缓存**。现在写进规范比事后回收便宜。提议条文：*程序的挂起与恢复只以账本为准；任何运行时续延（宿主的 async、effect handler、协程）只许作为同一次进程内的实现细节，不得成为恢复的依据，也不得让恢复路径绕过账本记账。*
>
> **同时提请注意一处现状与 §5 精神的张力（实测，非推测）**：`crates/jpp-cli/src/options.rs:3` 的帮助文本写着「Resume may perform unrecorded actions; replay rejects them.」——即 `--resume` 遇到账本里没有的 `do` 会**真执行**。对不幂等动作意味着可能重做。`13` §5 的「恢复时复用已完成记录，不能……自动重复付费」讲的是付费调用，同一条理由对 `do` 同样成立。探索者的判断（总控同意）：**正解是把动作记账做严，不是换成续延。** 具体怎么定归 Nature 与 Codex。
