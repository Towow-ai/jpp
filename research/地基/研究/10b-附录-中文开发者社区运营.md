# 中文 AI 开发者社区运营调研：Dify、FastGPT（补充 LobeHub）

调研日期：2026-09-25。主体选 Dify 和 FastGPT，LobeHub 只取它的 release 写法和贡献者致谢做补充。

**取证方法**：
- 发布日期和发布次数全部用 `gh api` 从 GitHub 拉取，不采用网页摘要里的日期。WebFetch 摘要曾把 2026 年误写成 2024 年。
- 公众号文章靠 exa 在 mp.weixin.qq.com 内检索，再读正文。本机缺 camoufox 浏览器，抓不到文章的发布时间，所以下文每篇文章只标对应 GitHub 版本的发布日期。
- 私域群内部的内容（群公告、@所有人）没有公开，查不到一手资料。第 4 节只列旁证。

## 1. Dify（LangGenius）

### 1.1 更新频率与内容结构

**GitHub Release 是版本通报的主渠道。**
- 共 170 个 release（10 个预发布）。第一个是 0.2.1，发布于 2023-05-15，正文只有一句“First Release”。
- 按年份：2023 年 40 个，2024 年 74 个，2025 年 38 个，2026 年截至 9 月 18 个。
- 早期约每月 5 个（2023 年 5–12 月）。现在约每月 2 个（2026 年 1–9 月，16 个正式版）。
- 链接：https://github.com/langgenius/dify/releases

**早期结构（2023 年 0.3.x）**：一段 Features（常常只有一两行，比如 0.3.9 的“支持 Claude-2”），接 What's Changed（逐条 PR 并 @作者），再接 **New Contributors** 和 Full Changelog。170 个 release 里有 126 个带 New Contributors 段。
- 例：https://github.com/langgenius/dify/releases/tag/0.3.4

**现在的结构（2025–2026）**：
- 标题写成“版本号 + 一句价值”，例如“v1.11.0 - Your knowledge base just went from mono to full HD”。
- 正文依次是：🚀 New Features（按领域分组，每条带 `by @作者 in #PR`）、🛠 Fixes & Improvements、Security、Environment Variable Changes、Database Migrations、**Upgrade Guide**（分 Docker Compose 和源码两种部署）、Contributors。
- 标题词频前几位：What's Changed 160、New Contributors 125、Upgrade Guide 82、各类部署小节约 80。
- 例：https://github.com/langgenius/dify/releases/tag/1.17.1

**“下一步”栏目很少出现。** 我统计了全部 release 正文，只有 1.9.0（2025-09-22）有一段 `## Future Plans`，列了调试工具、Human in the Loop、子图等 6 项。其余版本结尾一般只有一句“Keep the feedback coming”。
- 1.9.0：https://github.com/langgenius/dify/releases/tag/1.9.0

**里程碑会用来致谢贡献者。** v1.9.1（2025-09-29）的标题是“1,000 Contributors, Infinite Gratitude”，正文开头放了第 1000 位贡献者的庆祝图。
- https://github.com/langgenius/dify/releases/tag/1.9.1

**抽样看到的 Dify 公众号文章都只写重点版本或重点功能。** 抽样共 6 篇官方文章，因此无法断定它从不逐版转发：
- v1.0.0：https://mp.weixin.qq.com/s/HKgS7gmkGgVEC5uBKL6oag （GitHub 发布于 2025-02-28）
- v1.1.0：https://mp.weixin.qq.com/s/Zvyz9tS2jmPaLo7Bi9y5LA （2025-03-18）
- v1.6.0：https://mp.weixin.qq.com/s/LrwMA1vatWcyICaZHE7jaQ （2025-07-10）
- 多路召回：https://mp.weixin.qq.com/s/Kt6ZjfM0DRu6t8cawXY0jQ
- MCP 插件指南：https://mp.weixin.qq.com/s/CDhqmLO1JXSB__aUMqoGoQ
- Endpoint 发布为 MCP Server：https://mp.weixin.qq.com/s/Fmq1s4jE1HhOL_3lPmfHKA

这些文章的骨架基本一致：
1. 标题写“版本号：一句用户收益”。
2. 讲清是什么、为什么需要。
3. 给出分步教程，附截图和文档链接，也就是“怎么用”。
4. 用“写在最后”说明下一步。Endpoint 那篇写道：“未来版本将内置……敬请期待”。
5. 固定的结尾 CTA：GitHub 点 Star、在社交媒体和线下分享、贡献代码、试用云版本。v1.0.0 和“多路召回”两篇还加了一句“扫码添加 Dify 小助手，加入用户群”。

MCP 插件指南那篇在“写在最后”里点名感谢了贡献插件的社区开发者。

**第三方公众号会跟进二次传播。** v1.6.0 发布后，搜到至少 5 个非官方号写了解读或教程，其中一个是 yxkong（https://mp.weixin.qq.com/s/FG2IEJtbhLpjeVnHY1wgWw）。它们的发布日期没能核实。

**官网博客按类别分栏。** 栏目有 Release、How to、Research、Community、Event、Product、Company。2026 年 3–8 月约 20 篇，平均约每周 1 篇，分布不均匀。
- https://dify.ai/blog

### 1.3 私域与群

- **README 里没有微信群入口。** 2023 年 0.3.4 版的中文 README 也只列了 Discord、Twitter 和邮箱。现在的 README 列 GitHub Discussions、Issues、Discord 和 X。
  - https://github.com/langgenius/dify
- **微信群入口放在公众号文末**，写法是“扫码添加 Dify 小助手，加入用户群”，也就是先加个人号小助手，再由它拉群。见上面的 v1.0.0 和“多路召回”两篇。
- 群内公告和 @所有人 的使用规范，**没有找到公开资料**。

### 1.4 早期怎么吸引开发者参与

- **开源后一周内开始打 good first issue 标签。** 根据 issue events，#63 在 2023-05-18 打上这个标签，首个 release 是 2023-05-15。2023 年 5 月一共给 5 个 issue 打了此标签（#63、#90、#97、#155、#180）。累计 569 个，目前开放 12 个。
  - https://github.com/langgenius/dify/issues/63
- **0.3.4 版 README（2023-06）已经把贡献方式写全了**：
  - 贡献代码，指向中、英、日三语的 CONTRIBUTING；
  - 用 issue 反馈想法；
  - 分享案例，指向 dify-user-case；
  - 在 Meetup、博客、社交媒体上分享，并 @Dify 请官方帮忙转发；
  - 在 Discord 帮别人答疑。README 原话是“这也是个非常了不起的贡献”。
  - 想当社区维护者的人可以直接联系官方。
  - 同一份 README 还有公开的 **Roadmap** 小节，列了数据集、插件、开源模型三项。
  - https://github.com/langgenius/dify/blob/0.3.4/README_CN.md
- 从 0.3.x 起，每个 release 都点名 New Contributors。
- 现在的 CONTRIBUTING 公开了 issue 优先级表（核心功能 bug 为 Critical，依此类推），并把新模型和新工具的贡献引到独立的插件仓库。
  - https://github.com/langgenius/dify/blob/main/CONTRIBUTING.md

## 2. FastGPT（Labring / 环界云，与 Sealos 同属一家）

### 2.1 更新频率与内容结构

**GitHub Release 的节奏更快，并且多条版本线并行维护。**
- 共 276 个 release，其中 84 个是预发布。最早一个在 2023-08-09。
- 按年份：2023 年（8–12 月）27 个，2024 年 86 个，2025 年 97 个，2026 年截至 9 月 66 个。
- 2026 年的 57 个正式版里，44 个属于 **4.14.x 维护线**，其余是主线 4.15、4.16、4.17。可以看作“长期维护线 + 主线”双轨，并且带 alpha/beta 预发布。
- 仓库设计文档里自述：“FastGPT 以每周一次的频率进行发版”。
  - https://github.com/labring/FastGPT/blob/main/document/content/self-host/design/design_plugin.mdx
- Release 列表：https://github.com/labring/FastGPT/releases

**正文是中文。** 2024-11 到 2025-06 之间，多个版本在正文开头放“👀 新功能预览”配图，展示的是本版的新功能，不是预告（首次出现在 v4.8.14，例如 v4.9.0：https://github.com/labring/FastGPT/releases/tag/v4.9.0）。以 v4.17.0（2026-09-11）为例，依次是：
1. 升级说明：前置版本、必需的新组件、要删除的环境变量、镜像 tag 清单。
2. 弃用说明。
3. 🚀 新增内容（编号列表）。
4. ⚙️ 优化。
5. 🐛 修复。
6. 🛠️ 代码优化。
7. What's Changed（逐条 PR 并 @作者）。
8. New Contributors（这次有 10 人）。
9. Full Changelog。

链接：https://github.com/labring/FastGPT/releases/tag/v4.17.0

全部 release 的标题词频：What's Changed 112、🐛 修复 83、New Contributors 82、⚙️ 优化 77、🚀 新增内容 73、更新指南和升级指南合计约 97。

每个版本在文档站另有一页升级说明：https://doc.fastgpt.io/docs/upgrading

**FastGPT 写“下一步”的次数略多于 Dify，但也不固定。** 全部 release 里以“下一步”为标题的小节只有 v4.8.10 这一次，其余两处是正文里的一句话：
- v4.8.10（2024-09）有一段“4.8.11 版本预告”，注明“仅列出确定的功能”：https://github.com/labring/FastGPT/releases/tag/v4.8.10
- v4.6.7（2024-01）写了“根据社区针对高级编排的反馈，我们计划于 2 月份的版本中……”：https://github.com/labring/FastGPT/releases/tag/v4.6.7
- v4.11.0（2025-07）写了“调整 RoadMap，增加上下文管理……等计划”：https://github.com/labring/FastGPT/releases/tag/v4.11.0

**公众号**：没有检索到 FastGPT 官方号按版本发布的通报文章。能找到的官方或半官方内容挂在「Sealos」公众号或 fastgpt.cn 名下，而且是合作发布和科普，例如：
- 与焱融科技的合作发布：https://mp.weixin.qq.com/s/AUgdlKzYLxRGoQ3VE0VCJA
- Sealos 号上的本地搭建教程，作者署名“FastGPT 爱好者，Sealos Ambassador”：https://mp.weixin.qq.com/s/ECMU8puDhumDIonfsdYlUA

它的版本通报主要走 GitHub Release、文档站和飞书群。这是基于检索结果的推断，没有拿到公众号的完整发文列表。

### 2.2 案例征集、集成教程、活动与额度

- **插件共建是主要的共建机制。**
  - 插件从主仓拆到独立仓库。官方给的理由是：以前社区贡献插件“需要将 FastGPT 整个应用运行起来，并且直接向主仓库发起 PR”。
  - 现在分成 official、community、business 三个插件仓库，社区插件经基础审核后进入 Marketplace。
  - 插件系统说明：https://doc.fastgpt.io/zh-CN/plugin/intro
  - 开发指南：https://doc.fastgpt.io/zh-CN/plugin/system-tool-development
- **给 AI 代理用的贡献入口**（和 J++ 的受众直接相关）。`labring/fastgpt-community-plugins`（2026-06 创建，69 个 PR）的 `.agents/skills/` 下放了 4 个技能：
  - `develop-fastgpt-plugin`：一步步带新手完成插件并提交 PR；
  - `plugin-review`：在 PR 下发结构化的可发布性结论；
  - `plugin-discovery`：插件收录；
  - `daily-summary`：根据提交记录里的发布和撤销事件生成每日插件摘要，输出可以是 issue、评论或聊天消息。
  - https://github.com/labring/fastgpt-community-plugins/tree/main/.agents/skills
- **早期的集成教程靠社区。** 2023-07 的 README 列了“由社区贡献的宝塔部署和本地运行教程”（B 站视频）、公众号接入视频教程，以及“第三方生态”小节（企微机器人项目）。官方 README 直接给社区作品导流。
  - https://github.com/labring/FastGPT/blob/cf201267afa8537043874c0c8109285d03a634b6/README.md
- **额度**：
  - 云版免费档每月 100 AI Credits：https://fastgpt.io/zh/price
  - 模型接入文档里嵌了合作方 PPIO 的邀请码代金券，属于合作方的拉新动作：https://doc.fastgpt.io/docs/introduction/development/modelConfig/ppio
- 没有找到 FastGPT 官方的案例征集、征文或 hackathon 活动。

## 4. @所有人与群公告

**一手证据：没有。** Dify、FastGPT、LobeHub 都没有公开的群规或公告规范，也查不到有人讨论它们群内 @所有人 的频率。私域群内容不公开，这个结果在意料之中。

**可以核实的旁证**：
- **公开渠道承担“公告”，群只放入口。** 三个项目的公开公告都落在 GitHub Release、Discussions、Discourse 论坛（Dify 有 Announcements 分类，仅 4 帖）或博客上。公众号文末和 README 只放入群入口。
- **FastGPT 从微信群迁到飞书话题群。** 话题群按主题分线程，比微信群好检索。迁移原因官方没有说明，“好检索”是我的推断。

**二手经验（质量参差）**：
- 企微 SaaS 厂商有机云的教程（2026-08-25）主张“群公告偏必读、统一、低频”，“别拿公告当天天群发用”，群规要写进入群欢迎语和第一条公告。这是商业私域运营的做法，不是开发者社区的做法。
  - https://www.yjiyun.com/article/skill/41000
- 推群侠的营销文（2026-08-11）称频繁 @所有人 会触发微信风控，建议只在紧急通知和重大公告时使用，平时用置顶和群公告替代。这是营销号，可信度低，关于风控的说法无法核实。
  - https://www.tqxwx.com/marketing/6452.html

## 7. 对 J++ 的直接启示（我的归纳，供定稿参考）

1. **版本通报以 GitHub Release 为准，公众号和群只转述并附链接。**
   - 结构可以组合使用：FastGPT 的“升级说明放在最前 + 中文分节”，LobeHub 的“一句话摘要 + Known Gaps + 社区贡献者排在前面”。
   - J++ 在研究施工期，LobeHub 那种写明验证边界的“Release Validation & Known Gaps”最适合借用。
2. **“下一步”写成确定的清单。** 参照 FastGPT 的“下版本预告：仅列出确定的功能”。大段的愿景适合放在里程碑版本，比如 Dify 1.9.0 的 Future Plans。
3. **公众号只写里程碑版本，采用 Dify 的骨架。** 依次是：一句用户收益、为什么需要、分步用法、写在最后（下一步）、固定 CTA（Star、贡献、入群）。
4. **单独开仓库收用例，效果不好。** Dify 的 dify-user-case 只收到 2 条就归档了。用例征集要跟具体激励或活动绑定：讲者征集、模板免费代做、创作者市场、特别感谢计划。
5. **群的选型尽早定。** FastGPT 在第 16 个月从微信群迁到了飞书话题群，官方没有公开原因。“群的形态影响问答能否沉淀”这一依据来自春松客服的二手经验：微信群爬楼累，答案分散在多个群里。
6. **贡献入口可以直接写给 AI 代理。** 参照 FastGPT community-plugins 的 `.agents/skills`：新手开发向导、PR 评审和每日摘要都做成技能，每日摘要还能自动产出群内通报的文字。
