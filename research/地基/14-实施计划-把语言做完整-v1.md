## 一、这门语言现在能做什么（已验证，不是声称）

`.jpp` 源码 → 解析 → 检查 → 原生 Rust 执行，不依赖 Python。提交树 `2acf692` 干净 checkout 全绿。六种效应形式都有内置且能跑；方法是一等值，可传、可返回、可再组合；未决是一等出口且**必须被消费**（四条合法去向）；效应跟着类型走并在调用点实例化（rank-1 多态）；账本记账、重放零调用；`allocate` / `unsure_bound` 对照 Python oracle 逐条一致。

## 二、根缺口：执行模型没迁

**这是本轮盘点最重的一条，而且它此前不在任何待定清单里**——只活在 `crates/jpp-core/src/interp.rs:1` 的一句模块注释：「效应即时发出（惰性融合是后续优化，未迁移）」。

`12` §2.2 与 §4 要求的是**惰性登记 + 刷新点 + 分层**：登记后不发，到 `cut`/`fit`/`match`/`if`/读内容/程序结束时，把所有已登记且输入就绪的 `judge` 按状态分组、按依赖分层，一层一次发出。Rust 是逐语句即时执行。

**它是下面五条的共同根，一个决定动五行**：
- `judge(ss: [State], qs)` 向量化签名在 Rust 里写不出来（`12`:126）
- `12` §4 的编译 pass 只落地 1 个（ledger），提升 / 融合 / 裂变 / 下沉 / 调度 / 预算六个没有，**也没有任何开关机制**——而开关是消融的唯一载体
- `ast::Budget` 连 `layers` 字段都没有，J-07 的「层边界核」没有落点
- 同状态多题融合：代码路径成立（`effects.rs:26` 的 `judge(state, &[&Question])`、一次 `charge`、一次 `calls += 1`），**但仓库里没有一个测试钉住它**，全部 `judge(` 调用点都传单题。`12` §10 G2 判「满足」是对 Python 说的，在新内核上 P5 未验证
- 结构摘要 Φ 不存在，而 Codex 的回答指出：`ε={judge}` 不等于可融合，融合要的是站点/依赖/需求点/分支/顺序/循环/屏障

**排期：第一包。** 但先做最便宜的一格——补一条「两题一次调用」的断言（照 `tests/strength.rs:199` 的 `assert_eq!(outcome.cost.calls, …)` 写法），成本极低，不补则 G2 在新内核上没有依据。

## 十一、这一轮最有价值的产出：22 处「被包装成机制的 taste」

我给复核员的头号任务是揪出「写得像规则、实际无法写进检查器、无法被测试钉住」的条目。它揪出 22 处，**其中几处是我们自己写的**。记几条典型，作为以后的识别样本：

- **「在结果协议里预留字段」**——复核员判它「正好是任务点名的那种失败：造一个听起来像机制的壳来装 taste」。`Outcome` 上加一个 `goal` 字段，没有生产者、没有消费者、没有任何测试能因为它红。
- **「新增内置必须说明它是哪一种语言级操作」+ 遍历 BUILTINS 对照白名单的测试**——「这个测试只能验证有人给这个名字贴了一个分类标签，验证不了标签诚实。一个领域专用的 `search_bounded` 贴上『通用容器操作』就能过」。
- **「本版排除清单的棘轮」**——「加一节文档不构成棘轮。没有任何东西能检测『悄悄删了一项能力』——恰恰因为它是悄悄的」。
- **「优化器必须声明依赖了哪些效应画像」**——「没有任何检查器能验证这份声明是真的或完整的；声明写得漂亮而 pass 照样偷跑，测试一样绿」。
- **`unsure_bound` 的「独立估计只作参考不作判据」**——最隐蔽的一例，因为它被一条真机制掩护着：这条纪律**只写在注释里**（`strength.rs:70-78`），没有任何东西阻止调用者拿 `independent_any` 当判据。

**由此立一条识别法则**：一条规则若**说不出「什么情况下它会让什么东西变红」**，它就是 taste，不管措辞多像规则。写进文档可以，**不许记成「已落实的机制」**。
