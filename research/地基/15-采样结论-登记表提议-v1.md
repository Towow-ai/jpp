## 零、采样最重的一个数

**六条缝里五条（批调度 / 深度与终止 / 预算 / 缓存 / 校准），在 30 个教学样本里是 0 实现**，而正文 12 处以上用散文提醒「应该做」。同样五条在 4 个第三方**生产**仓库里：预算 4/4、批调度 3/4、缓存 3/4、深度 2/4、校准 2/4。

**唯一教学材料肯写代码的缝是弃权：9 处真实现，8 种互不相同的机制**，阈值 0.30–0.90 不等。

> **缝只有真把东西跑起来的人才会撞上，而撞上的人各写各的。没有共同形状。**

一条实证的佐证：社区 playbook 里写好了一个通用三态弃权函数 `safe_route`，**同仓库内零调用**，四个场景各写各的 if 链。**这是库的失效方式——好抽象存在，没有东西逼你走它。**

## 一、建议新增的登记行

### R1 · 保守聚合（取最坏，不取平均）

| | |
|---|---|
| **借的东西** | 安全关键系统的最坏情况合成：优先级格（precedence lattice）、最弱环节取 min、任一触发即升级 |
| **当年解决的问题与条件** | 多个独立信号合成一个处置；信号同质、误差独立，平均是无偏估计 |
| **条件在 Jev 下怎么变了** | 读数不同质（I3：跨题不成恒等式）；误差不独立（红队：Jev 的错是对这份 state 的系统性误读，不是随机噪声）；**平均会把一个高危信号稀释掉** |
| **由此发展的新机制** | 聚合子加一档「保守合成」：位取 ∨、索引取优先级格上的上确界、档取 min。**任一分量 unsure 则结果 unsure**（不许被多数稀释） |

**证据（5 处独立实现）**：护栏 cookbook 的 `PRECEDENCE` 取最严处置；SDE 级联 `any_flag` 任一字段告警即升级；日期抽取 `confidence = min(...)`；function calling 的 confidence 取「最弱判断」而非乘积；理赔/审核的三段式。**三种数据类型、五份独立代码、同一个哲学。**

**我们今天没有**：聚合子只有 exists/all/count、mode/hist、dist/median/top-k，没有保守合成这一档。

---

### R2 · 确定性预筛 → 模型只做窄判断

| | |
|---|---|
| **借的东西** | 查询优化的谓词下推、编译器的常量折叠：能用便宜确定手段先削减的，不交给贵的一步 |
| **当年解决的问题与条件** | 贵算子的输入基数决定总代价；确定谓词可证等价，下推不改语义 |
| **条件在 Jev 下怎么变了** | 贵的那一步不是 CPU 是**字面化程度**——Jev 不会数数、算术、比日期、多跳（官方 jaggedness 自陈）。所以下推的不只是为省钱，**是为把不可判的形状变成可判的** |
| **由此发展的新机制** | 把「确定性预筛」升为一等构造：`do` 的输出带「已削减到什么形状」的标注，检查器据此判这道题是否一跳可判（字面化定律的可执行化）。**不可判的题在静态就报，不是跑完才发现读数没意义** |

**证据（8+ 处独立出现）**：引用检查先做字符串匹配预过滤；重排先用 BM25 粗筛到 30 个候选（法律检索 top-1 5%→18%）；值抽取先用正则找候选；jevcal 的零 key 静态 lint 扫问题措辞弱点；jev-belay 的正则预筛；jev-reranker 的分段后处理（让代码保证语义边界，不依赖模型分段）。

**与我们已有的关系**：能做域表已有「抽取类 | 确定性枚举器 | `gen` 的零成本实现」一行，**但它停在纸面，且方向写反了**——登记的是「用枚举器补 Jev 写不出的」，实测反复出现的是「用枚举器把输入削到 Jev 判得动」。

### R3 · 答案空间自带弃权档

| | |
|---|---|
| **借的东西** | 决策论的拒绝选项（Chow 1970）——但**落法不同** |
| **当年解决的问题与条件** | 在校准后验上按代价定一条阈值，落在带内就弃权 |
| **条件在 Jev 下怎么变了** | 阈值要标定，而标定要标注集，**而绝大多数人没有**（采样：阈值全标「示例值，非标定结果」）。**但如果档位本身就对应动作，阈值这一步整个消失** |
| **由此发展的新机制** | 题的构造上加一条检查：**选择题的候选集必须含一个「都不是/需人工」的叶子；打分题的档位必须逐档对应一个确定动作**。满足的，`cut` 不需要线也能出口；不满足的，报 W 并要求校准记录 |

**证据**：实体对齐 cookbook 的三档 score 直接对应合并/送人工/不合并，**正文明确论证「不需要拟合阈值」**；社区 pattern 反复强调在选项里放 other/review 强制叶子。采样代理把这条判为「弃权得以被表达的上游前提」。

**我们今天没有**：`select` 的 unsure 是结构性出口（`handle` 必须写 unsure 臂），**但题本身不强制带 other 候选**。

---

### R4 · 不确定性采样必须掺强制探索

| | |
|---|---|
| **借的东西** | 主动学习的不确定性采样（uncertainty sampling） |
| **当年解决的问题与条件** | 标注预算有限，挑模型最不确定的标，收敛最快 |
| **条件在 Jev 下怎么变了** | Jev 的错是**系统性字面误读**，不是随机噪声。于是存在一整类样本：模型**自信地一直错**，因此永远排不进「最不确定」的前 k，**永远不被抽到，也永远不被发现** |
| **由此发展的新机制** | `allocate` 的配额分两份：按不确定度降序取 k−e 条，**强制随机探索 e 条**。e 的下限进档案，不许为 0 |

**证据**：`jev-align`（sutro-sh，846 行）`select_batch` 显式 `exploration_count`，理由原文是防止「自信地一直错在同一类样本上却永远不被抽到」。

**这是我们 `allocate` 的一个真缺陷**：现实现是纯按不确定度降序取前 k（`strength.rs` `allocate_report`），没有探索项。

---

### R5 · 弃权的去向可以是「标注」，不只是「处置」

| | |
|---|---|
| **借的东西** | 人在环（human-in-the-loop）的复核队列 |
| **当年解决的问题与条件** | 机器不确定的单子交给人，人处理完这一单就结束 |
| **条件在 Jev 下怎么变了** | 人给出的那个答案**同时是这道题的真值**。而真值是校准线的唯一来源（J-03）。所以同一次人工，既处置了这一单，又产出了让以后所有同类单子更准的证据 |
| **由此发展的新机制** | J-05 的四条合法去向加第五条：**`label`**——把未决连同人给的答案一起折进校准记录。真值通道由此第一次有生产者 |

**证据**：`jev-align` 原文——「弃权的去向不是转人工审核这一单，是转人工标注，用来改进以后所有类似单子的判断」。

**我们今天卡在哪**：`interp.rs:1478` 运行期把 `label` 写死 `None`（注释自陈「真值通道是未定的另一样」），全仓 `label: Some` 只出现在测试夹具里。于是 `commission` 在真实路径上永远拒绝（「没有带标注的样本」），`unsure_rate` 恒 `None`，J-10 的界恒等于 n。

### R6 · fit 集选优、holdout 集验证才接受

| | |
|---|---|
| **借的东西** | 机器学习的训练/验证集分离 |
| **当年解决的问题与条件** | 防止在选型时过拟合 |
| **条件在 Jev 下怎么变了** | 被选的不是模型参数，是**题面措辞**和**阈值**。而题面措辞的过拟合没人防——采样显示改问法比改阈值影响更大（消融：17 块 vs 12 块） |
| **由此发展的新机制** | 已有 J-16（fit 的训练集 ≠ 保形集）**扩到题面**：任何由数据选出的题面变体，必须在 holdout 上不劣于原版才接受，否则保留原题面 |

**证据（两个独立项目殊途同归）**：`jevcal` 的 `_beats_on_holdout`；`jev-align` 的 `optimize_candidate` / `evaluate_labeled_candidate`。两个完全独立的第三方各自重新发明了同一套接受判据。

---

### R7 · 沿条件链的链式法则（I3 拆两条）

| | |
|---|---|
| **借的东西** | 层次分类的 beam search 路径打分：各层概率连乘 + 按深度几何平均归一 |
| **当年解决的问题与条件** | 在一棵概率真实的树上找最可能的路径 |
| **条件在 Jev 下怎么变了** | 每层是校准输出不是真概率；链式法则只在「第二层在第一层选对的条件下也校准」时成立，**而那是比逐层校准强得多的主张，没人测过**（误差累积：九成准十跳剩三成五） |
| **由此发展的新机制** | I3 拆两条：**(a) 不相关题的读数不可合成——保持禁止**；**(b) 同一条件链上的读数可按链式法则合成，但校准键必须带条件（父节点进键），未记录的按 J-15「未测」取保守** |

**证据**：官方层次分类 cookbook，beam K=3，`product(edges)**(1/decisions)`，深度上限 12，4 个案例 beam 全对、贪心只对 2 个。**这套做法我们今天写不出来**（I3 禁跨题算术，J-01 把算术挡到宿主）。

**附带**：几何平均那一步不是概率是排序分（按深度归一让长短路径可比），作为排序依据不需要是概率，风险比看上去小。

## 二、建议订正的已有登记行

### C1 · 「推测执行」那一行的条件写错了

**原行**：推测执行 → 刷新点向前推测同帧可求值的 judge 站点并入本层；推错记 `W-spec-unused`；超预算先丢推测。

**采样照出的问题**：官方的 **Speculative Fan-Out 根本没有「推测」这一步**——它是把全部可能用到的问题（含大概率白问的）**一次性塞进同一个请求**，事后在答案里筛。全程一次调用，没有独立的「猜」和「丢」。

**原因**：同状态下加一道题的边际成本≈0（P5）。**成本为零的地方，「推测」这个概念本身是多余的**，那本「白花」双栏账在记一个等于零的量。

**建议订正**：把推测执行拆成两格。**同状态**：不推测，全问（无需白花账）。**跨状态/跨分支**：仍是推测，因为要多付一次状态读入，白花账在这一格才有意义。

**我们的实现现状**：`speculate` 的白花双栏账只在一个程序形状上量过（交接第三·五节自陈「它比看起来弱」）。

---

### C2 · 「自洽性投票」那一条，我们否得对，但理由该换

**我们的原判**（总册 §14）：多措辞、多数表决降错——**不采用**，因为 Jev 的错是系统性字面误读，不是随机噪声。

**采样的发现**：官方两篇 self-consistency cookbook **本来就不是投票**。它们测的是「同一道题重复问的方差」，用来证明**单次调用就够稳、可以只调一次**。有效区间是概率**远离切点**时；失效是概率**贴近切点**时会翻面（两篇都点名了具体哪道题翻了）；**对策是设一条弃权带把翻面区间送人工，不是靠投票定案**。

**建议**：结论不变，理由加强——**厂商自己的数据给出了失效位置（切点附近）和对策形状（弃权带）**，而那条带就是我们的 ±δ。这条从「我们的判断」升级为「有外部数据的判断」。

---

### C3 · 「能做域表」里枚举器那一行方向反了

见 R2。原行写的是「用枚举器补 Jev 写不出的任务」，实测 8 处反复出现的是「用枚举器把输入削到 Jev 判得动的形状」。**建议按 R2 改写该行第四列。**

## 三、采样照出的、我们该记下的三个外部事实

1. **官方 SDK 六条缝一条都不管**（`typesafe-sdk` 0.7.1 / `@typesafe-ai/sdk` 0.6.0）：无批调度（每次 `system_one()` 一个独立 POST）、无并发限流、无缓存、无预算、无校准、无深度。只管传输层重试（2 次、500ms 起指数退避封顶 5s、25% 抖动、429/408/5xx、尊重 `Retry-After`）。**一次请求挂多少题没有上限。**

2. **人们感觉到需要调度，于是去借 DAG 引擎**：官方集成里有 Apache Airflow、Pydantic AI、Composio、Arize。132 个仓库依赖两个 SDK（Python ~110 / JS ~22），领域分布 AI 代理 35%、LLM 应用 19%、工作流 11%、评测 11%、金融 8%。**而 Airflow 那类东西不认识校准、不认识不确定、不知道该不该往下走。**

3. **题型分布跟任务域走，教学语料的均衡掩盖了生产里的偏斜**：教学 30 样本 noul≈18 / choice≈17 / score≈13（刻意示范，不能当从业者证据）；业务 cookbook 偏选择题（7/7）；研究 cookbook 偏打分题（≈76%）；第三方生产工具偏是非题（3/3，打分题一次未单独挑大梁）。**三种都承重，`06` 那条完备性论证（位/索引/数各管一类控制点）站得住。**

## 四、一个真实事故，它同时演示了两种失效（社区采样，日志分诊）

一位开发者用 Jev 做日志告警分诊。一次真实事故：**47 分钟的复制延迟**，Jev 给出的概率是 **0.24–0.31**，而他的代码把读数丢掉、只留离散三分类的 argmax，**选错了桶，事故漏报**。

他的修法是**改问法放宽标准**。结果：假警报从 **0 冲到 189**。

**这一个案例同时命中我们两条设计主张，而且两次都是反面：**

1. **把读数拍成一个离散出口，就把「离决定带多远」这个量扔了。** 0.24–0.31 在一条标定过的线上会落进弃权带，出口是 unsure 不是一个错桶。这正是 J-01「读数只经桥离开」与 `cut` 的 ±δ 要保护的东西——**他丢掉的恰好是 Jev 唯一独有的那个量。**
2. **改题面没有 holdout 就上线，代价是 189 条假警报。** 这正是 R6 要求的：任何由数据选出的题面变体，必须在 holdout 上不劣于原版才接受。

**这是采样里最完整的一个「不用这门语言会怎样」的实例，两个失效模式都有真实数字。**

## 五、三条来自社区的外部事实，都该记下

1. **「不会幻觉」只保证格式合法，不保证语义对。** 几乎每篇实测文独立重新发现一次；**创始人本人在 HN 上也认了「可以自信地答错」**。这与红队那条「Jev 的错是对这份 state 的系统性误读，不是随机噪声」是同一件事，现在有厂商自证。

2. **官方基准的「正确答案」是两个通用模型的共识平均，不是人工 ground truth**，被广泛吐槽「GPT-6 and Claude wrote the answer key」。**这正是我们 `CalibRecord` 要有 `label_source` / `label_set_id` 两个字段的理由**——谁做的标注决定那条线值不值钱。外部证据表明这是整个生态最普遍踩空的一格。

3. **从业者最大的抱怨是：只给数字不给解释，拿不到能用来改进系统的方向性信号。** 这条是产品机会而不只是缺点：账本记下了是哪道题、哪份材料、哪条线产生的出口（`line_source` / `derived_from` / 账本头），而二阶让题集可以被系统地变动——**「哪一道题在推动这个数」本身就是一次差分**。这门语言结构上答得了这个抱怨，而 SDK 答不了。

## 六、二阶这块地，确认是空的

- **没有找到任何开发者自己做「用 Jev 的输出决定下一轮问 Jev 什么」的一手案例**（社区采样 26 个来源）。
- 官方旗舰 autoresearch 是「**另一个贵的通用 LLM 提问、Jev 只管答、代码判优**」，停止条件硬编码 5 轮，文档自陈没做自适应终止。
- 唯一两个真的从上一轮结果构造下一轮的，都是**确定性构造**：skill-suggestion（182 选 1 → 取 top3 切片 → 构造第二轮选项集与逐候选 noul，第二轮还能整体否掉）、function calling（读函数类型签名自动生成 54 题）。

**所以 `derive` 有两条路，且都未被占：用 `gen` 提议（贵、官方在用），或从上一轮的结构确定性地长出来（便宜、被证明能跑）。后者应当是默认。**

## 七、第八条缝：能力可用性门禁（新增，证据最强的一条）

**〔2026-09-22 补，来源：GitHub 采样 26 个真实样本 / 22 个仓库 / 8 种语言〕**

| | |
|---|---|
| **借的东西** | 可选依赖的优雅降级：功能开关、空对象模式（Null Object）、能力探测 |
| **当年解决的问题与条件** | 可选组件缺席时程序仍要良构；组件是确定的，在或不在是一个静态事实 |
| **条件在 Jev 下怎么变了** | 缺席的不是一个库，是**判断力本身**。而这门语言里判断是唯一的非确定运算（G1），所以判官缺席时，**每一个出口都失去来源**——不是少一个功能，是整棵控制流没有驱动。且缺席有多种形态：无凭据、无档案、无校准记录、模型版本不兼容，**它们在账本上必须分得开** |
| **由此发展的新机制** | 「判断力不可用」升为一等状态，与 `Unsure` 并列而不混同：**`Unsure` 是问过了不确信，「不可用」是没问成**。出口带 `cause` 区分两者；档案缺席、凭据缺席、记录缺席各有自己的 `cause`；程序在判官缺席下仍须通过静态检查（能写出「没有判官时这条路走哪」），而不是运行期抛错 |

**证据（5 份独立实现，5 种语言，互不知晓）**：凭据缺失时让 Jev 结构性地「不存在」而非报错——JS `return null`、Python `return None`、Go `return nil`、Rust `Option::None`、Bash `exit 0`。采样代理的判断：**这条比六条缝里任何一条的跨项目一致性都高，最像生态共识。**

**与弃权的区别（必须分开，否则路由错）**：弃权是**调用后答案不确信**；本条是**调用前判断力不在**。触发条件、处置、以及「以后能不能变好」都不同——弃权可以靠标注收窄，不可用只能靠补齐配置。

**与我们已有机制的关系**：`Profile` 的 `Tri`（未测）、J-15（未测字段取保守）、冷键 → `Unsure(cold)` 都邻近但都不是它。**冷键是「有判官、没有线」，本条是「连判官都没有」。** 我们今天没有这一格。

**这条同时是「换个接口就行」的运行期落点**：判断力可插拔，就必然有「这次没插上」这个状态。

### R9 · 时延预算与代价预算并列

| | |
|---|---|
| **借的东西** | 资源预算 / 资源感知类型（已在登记表，第三列写的是「成本几乎只取决于调用次数（P5），静态可估」） |

### R10 · 「先选后填」是题型逼出来的结构，不是模型能力的选择

| | |
|---|---|
| **借的东西** | 工具路由 / 函数分派 |
| **当年解决的问题与条件** | 由生成模型一次性吐出「调哪个工具 + 参数是什么」的结构化输出 |
| **条件在 Jev 下怎么变了** | **Jev 不生成**。选择题只给一个索引，所以「选哪个」和「填什么」在物理上不可能是同一次调用。**两步不是设计取舍，是题型的直接后果** |
| **由此发展的新机制** | 把「先选后填」立为骨架的一项（`dispatch`）：第一步 `select` 定索引，第二步按选中项的**类型签名**确定性地生成参数题（见 R2 与 function-calling 的 54 题）。**第二步的题从签名长出来，不由人写**——这同时是 `derive` 最便宜的一条实现路径 |

**证据**：工具路由加填参数的场景在采样里**清一色收敛成两步调用**（composio 的工具路由引擎、cua、pydantic-ai、vercel/ai 等）。采样代理的判断：「不是模型能力选择，而是 Choice 题型本身逼出的结构。」

**为什么值得记**：这是整个生态里**最普遍的一个惯用法**，而它的成因是原语的形状。**原语的形状决定程序的形状**——这正是一门语言该把它命名下来的那类东西。

## 十二、最后一条登记行：终止要三条独立的线（来源：jevable 194 项目源码追查）

### R11 · 深度的终止条件必须多于一条，且不能有任何一条是模型自己说了算

| | |
|---|---|
| **借的东西** | 燃料有界递归（已在登记表：「`bound` 必填；耐心变式；键重复即停」） |
| **当年解决的问题与条件** | 证明终止；被证明的对象是确定性递归，一条良基序就够 |
| **条件在 Jev 下怎么变了** | 循环的推进量由**判断**给出，而判断会系统性地错（创始人自认「可以自信地答错」）。**一条线不够**：步数上限管得住死循环，管不住「每步都合法但一直原地打转」；无进展检测管得住打转，管不住「模型觉得还没完」 |
| **由此发展的新机制** | 终止条件是**一组**而非一条，且必须至少包含一条**不依赖判断**的线。`loop` 的签名从「一个整数上界」扩成三格：**步数上限**（确定）、**无进展判据**（确定，键重复即停）、**完成判断**（判断给出，但**单独不足以终止**，必须与前两条合取）。只写完成判断的程序静态报错 |

**证据（4 个真多轮循环，清一色三重熔断）**：JevPlaysPokemon（宝可梦对战）、typesafe-computer-use、touchpress（端到端测试）、jevthoven（逐小节生成音乐）。采样代理原话：**「步数上限 + 连续无效动作检测 + 模型自认完成，三重熔断，没有一处纯靠模型自己喊停。」**

**我们今天**：`loop(bound, init, step)` 只吃**一个整数上界**。宪法登记表的 Datalog 那行写了「无进展键重复即停」，`12` 的 handler 库也列了 `noprogress → 退出记账`，**但 `loop` 的签名里没有这一格**，程序写不出来。

**最干净的一个实例值得单记（JevPlaysPokemon）**：外层 `while(!battle.ended)` 驱动一个**确定性的对战引擎**，每回合把结构化状态（HP / 属性 / 技能 / 天气）转成题面，**问一道选择题**，拿到落子立刻回填引擎推进下一回合。终止靠「引擎判胜负」和「maxDecisions 硬顶」两条独立线。README 原话：**「没有对低置信度答案做脚本化替换。」**

> **这是 R2（确定性引擎削减形状）与 R10（选择题只给索引）合起来的完整形态：确定性引擎驱动世界，判断只负责每一步选一个动作。**

## 十六、补一条登记行：线要带「这批标注有多可信」

### R12 · 标注一致性统计进校准记录

| | |
|---|---|
| **借的东西** | 循证医学的双审阅者一致性（Cohen's kappa）与 PRISMA 方法学报告 |
| **当年解决的问题与条件** | 人工筛文献时两个人会不一致；kappa 量化「这批标注本身有多可靠」，低于阈值就先统一标准再继续 |
| **条件在 Jev 下怎么变了** | 我们的线来自标注集（J-03），**而标注集的质量决定线的质量**，这一点在整个生态里被普遍忽略：官方基准的「正确答案」是两个通用模型的共识平均（社区吐槽「GPT-6 和 Claude 自己写了答案卷」）。**一条线可以形式上合法而实质上一文不值** |
| **由此发展的新机制** | `CalibRecord` 增一格：标注一致性统计（双标注者 kappa 或多模型一致率）与其样本数。**低于档案给定下限的线，`cut` 只能切出 `Unsure`，并在出口留痕**——与冷键同一条路由，但 `cause` 不同（`cold` 是没有线，本条是线的证据不可信） |

**证据**：`jev-reviewer`（choxos）——循证医学文献抽取工具，两遍 screen→verify，**五级阈值（0.02 / 0.3 / 0.5 / 0.25 / 0.3）分工极细**，内置**双审阅者 Cohen's kappa 一致性统计**与 PRISMA 方法学段落自动生成。采样代理的判断：**「这批里唯一把标定做成产品功能而非私人调试记录的样本。」**

**我们今天**：`CalibRecord` 有 `label_source` / `label_set_id` / `label_fp` / `label_locator`，**记得住标注从哪来、是哪一批、指纹是什么，却记不住它有多可信**。而我们自己的 E-CAL 实验里已经在算两模型一致率了（赌值 noul ≥ 0.85 / choice ≥ 0.80 / score 相邻档 ≥ 0.85）——**那个量已经在算，只是没进记录、没进语言**。
