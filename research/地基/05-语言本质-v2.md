## 0. 一句话

语言的内核是**两个类型、一道题、三值、五个算子、一本账**。
「判断可以反复判断自己的结果」仍然成立，但它不是一个递归函数，
是内核之上的四个骨架。任务无关的是内核和骨架，任务只提供最外层的问题和料库来源。

## 1. 内核（形式定义，一页）

**类型两个。**
- 材料 `M`：任何来源、任何格式的数据，带地址、来源链（about / made_by）、渲染函数
  `render: M → Text`。Item 就是 M。Kind 是 M 上的标签，不是类型。
- 读数 `R_q`：问题 q 的一次判断结果。每个 q 一个类型。跨 q 不可加、不可比。
  **R_q 没有渲染函数**：概率永远不进 Jev（红队 A5；Jev 不做算术，E7 已测）。

**桥一座。** `outlet_q : R_q → {act, ignore, unsure}`，用 q 自己的两条线（校准给出）。
出口是 M 的一种（可以渲染、可以当材料），读数不是。
这是概率进入下一轮的唯一通道。

**一道题。** `jev : M × Q⁺ → R`。一个状态挂多题，一次请求。
状态渲染后受界限约束（带主张的材料约 500 token，E5/E6）。

**三值。** 强 Kleene：`∧` 有假即假、无假有 unsure 则 unsure；`∨` 对偶；
`¬unsure = unsure`；`¬` 不等于反问（P(x)+P(¬x)≠1，v0 §1.3），
反问是另一道题带自己的线。存在 = max，全称 = min（Mostowski）。

**五个算子。** 全部 `Set[M] → Set[M]`，每个算子的签名里写死 unsure 的去向，
没有隐式二值化（SQL NULL 三十年的教训，研究 §5.2）：
- 过滤 `filter(S, q)`：输出三条流 act / ignore / unsure，unsure 是第三条流，
  由骨架决定它进下一层、细拆再判、还是升级给人。
- 配对 `pair(S, T)`：笛卡尔积，每对渲染成一个状态，对象段结构化标出。平方项。
- 聚合 `agg(S, op)`：存在 / 全部 / 计数 / 前 k。计数给区间 [act, act+unsure]；
  前 k 里含 unsure 则结果标 unsure。
- 递归 `iterate(f, S, bound)`：**有界迭代**，不是不动点。每层状态 token 数严格递减，
  或步数到上限。Jev 非单调（E5/E6 加材料会翻出口），不动点不存在（红队 A6）。
- 做 `act(a) → M`：对世界执行动作，产出新材料进料库。有副作用，
  代数律（两次过滤 = 一次合取过滤）只对不含「做」的子表达式成立。

**一本账。** 每次 jev 调用的（渲染后的状态、题、读数、出口）入账本，只增不改。
重放 = 沿来源链按账本重算，逐字节相同。账本键建在渲染后的文本上，不建在源字节上
（OCR 不确定，红队 B7）。

**校准。** 沿用 v0 §5.4：编译期验题闸门，运行期错误率扫描，超线停岗。
线只从标注数据来，禁止手调。这是六个先行系统的共同空白（研究 §8）。

## 2. 骨架（标准库，四个）

每个骨架是内核算子的一种固定组合，带终止证明。
验收标准：换任务只改最外层 Q 和料库来源，第三处不同就是骨架锁住了（四任务 diff）。

| 骨架 | 适用 Q | 结构 | 终止 | 实测 |
|---|---|---|---|---|
| 筛 | 一元 | 前提过滤 → 逐段问 Q → 聚合 | 每段一状态，一层到底 | E8：一元题对关系型 Q 无意义 |
| 配对 | 二元 | 前提过滤 → 配对 → 每对一状态挂多题 → 聚合 | 每对 ≤ 2 段，三层两轮 | E8：74 段→35 段→595 对，20 s，$0.014 |
| 分治 | 全局（「这篇自洽吗」） | 拆成 ≤ 界限的块 → 各块问 → 各块**出口**渲染成摘要 → 再问 | 每层 token 严格递减 | 未测 |
| 搜索 | 交互（computer use、Agent） | 做 → 观察 → 判（多题）→ 定（choice → 动作）→ 做；带已访集合和不可逆闸门 | 步数上限或找到 | 未测 |

纯过滤递归（v1 §8）不是骨架：对同质材料是恒等映射，E8 实测第二层 token 一点不减。

## 3. 材料价值三类，顺序固定

- **证据**：让 Q 动。用字面前提谓词判（「这段有观点吗」），不用元题
  （「有助于判断 Q 吗」E8 实测无区分力：72% 读数 < 0.2）。证据必须绑定判断对象，
  状态渲染结构化标出哪段是对象、哪段是证据，对象段单独占位（红队 A7，E5 带偏）。
- **语境**：让证据的意思变。分两种：问题语境（定义、约定）在证据**之前**选，
  因为它决定谁算证据（红队 B3）；证据语境（谁说的、是否引用）在证据之后。
- **参照**：改变问题的刻度和参照类（score 的样例档、choice 的选项、排序的同批候选）。

顺序：问题语境 → 证据 → 证据语境 → 参照 → 问 Q。任务无关。
「不重复」是经济性，不是本质。

## 4. 谓词推导（二阶，条件于目标）

从目标推出这次任务的谓词表，推导程序任务无关，表每次不同。三步：
1. **前提**：规则给出的逻辑必要条件（矛盾 ⇐ 有观点）。是第一个**判**层，
   前面可以有「做」（截屏）。
2. **区分**：LLM 海选候选谓词，在**带标签**的样本上筛。筛选**条件于目标**：
   先按对目标的区分力（正负样本上读数分布的距离），再按冗余去重
   （mRMR 的 D − R 形状，红队 A4 与研究 §4 独立得出同一结论）。
   稀有目标必须分层抽样把正例抽够；没有标签时只允许保留前提谓词，表标「未验证」。
   样本少于几十时互信息估计严重有偏，退化为方差和一致率。
3. **多层**：第二层以后的谓词在第一层分流后的子样本上重算条件区分力（ID3 式），
   不用一开始的边际统计。代价：层越深样本越少。
元题只许出现在这一步的编译期，产物过验题闸门才能当谓词。

## 5. 成本模型与规划器

实测（E8，1,088 次 HTTP）：
```
每次调用 token ≈ 271 + 1.00 × 状态字符 + 0.88 × 题字符     固定开销在小片段上占 77%
p50 0.86 s，p95 1.0 s，与题数几乎无关
并发 8 ≈ 9 次/s，并发 32 ≈ 35 次/s，0 次 429/529（上限只知 ≥ 32）
两题合一请求比分两次省 45% token
```
所以：
- 钱 = Σ 调用 (271 + 状态 + 0.88 × 题)。「问题免费」只在时间上成立，token 上每题约 38。
  成本单位是**调用次数**，与所有先行系统一致；差别是我们一次调用能挂几十题。
- 时间 = 层数 × p95 + 状态数 ÷ 并发。层的耗时是该层最慢的状态，尾延迟决定一切。
- 配对是平方项：1,000 段幸存 47% → 11 万对、$2.5、1.6 小时。
  **规划器首要职责：压小配对前的幸存集。**
- 目标函数：在「每个状态 ≤ 界限」约束下，按（层数，钱）字典序最小；
  或在用户给的时间预算内最小化钱。「状态数最少」单独作目标会撞界限（红队 B6）。
- 排序判据：`rank = (选择率 − 1) / 代价`（Predicate Migration），不是简单先便宜后贵；
  一元选择率接近 1 而二元选择率极低时顺序要反过来（PLOP 已证先过滤后连接不总最优）。
- 重规划锚点：层边界（一次往返的物化点），不做逐元组路由（AQE 的教训，研究 §3.4）。
- 依赖分层：半朴素求值的 full/delta/new 三分与依赖图取 SCC 按拓扑序分层，原样搬用。
- 选择率估计：离线用免费的题标注代表性样本建目录，在线分层重要性采样（SemStats 思路）。

> 2026-09-23 注：规划器价值函数 = 效用准则 × 可靠性折扣，按状态算价值密度，切分点由校准后的信道给出（Jedynak 2012：不对称信道 u* ≠ 1/2）。〔依 Nature 2026-09-23 授权，Fable 裁定 B7（地基/附注/2026-09-23-决策单B栏-Fable技术裁定.md）；六项见该文件 B7 条与 §三〕

## 6. 与先行工作有证据的差异（研究 §8）

1. 逐判断校准概率：六个语义算子系统都没有。
2. 一状态多题近乎零边际时间成本：没有一个规划器把它当一等假设，它们全在减少调用次数。
3. 账本重放而非缓存命中：DocETL 只有工程缓存；LOTUS、Palimpzest 承认两次运行结果可能不同。
4. 分解逻辑放在语言的显式骨架里而非优化器黑箱里（DocETL 的 13 条重写在运行时不对用户暴露）。
   这是位置差异，不是优劣结论。
5. 三值在每个算子签名里显式化：先行系统多数没有三值，直接丢掉可信度信息。

## 9. 缺位：选择题与打分题（Nature 2026-09-20 深夜指出，待 v3）

**事实核对。** 昨晚的运行时三种题型都支持（outlet.py 处理 choice/score；试验台 A 有
2 个 choice 单元、1 个 score 单元；校准对 choice 每选项 ≥2 验题、score 每档 ≥2）。
但**组合层**只有一种形状：一切读数经 outlet 压成 act/ignore/unsure，五算子全建在
这个三值上。E8 原型只用了 noul。v2 §1 的桥只有一座，choice 只在搜索骨架里出现一次。
所以：原语层没锁死，组合层锁死了。

**三种题各是什么运算。**
- noul：一元谓词。材料 → 概率。只能筛。
- choice：**比较**。一个状态里 N 个候选 → N 上的分布（Σ≈1）。相对判断，
  一次调用不是 N 次，每选项约 38 token。
- score：**有序**。材料 → 档位上的分布。排序、分级、程度。

**v3 要改的。**
1. 桥改为三座：`outlet_noul → {act, ignore, unsure}`；`outlet_choice → 选项 ∪ {unsure}`
   （分布最大值不过线或前两名差距不够即 unsure）；`outlet_score → 档位 ∪ {unsure}`。
2. 算子加两个：**选** `select(S, q_choice) → 一个 M 或 unsure`（K 选一）；
   **序** `rank(S, q_score) → 有序 Set[M] 带档位`。
   配对的一部分被「选」吸收：对每段 a，一个状态放 a + K 个其它段，问「哪段与 a 矛盾」，
   N²/2 个状态变成 N × N/K 个；E8 的平方项和规划器的首要职责要按这个重算。
3. 骨架加**锦标赛**：生成 N 候选 → 每 K 个一状态「选」→ 胜者再选 → 直到一个或 unsure；
   unsure 触发再生成。这是 `find x : J(x)` 的实现。
4. 谓词推导的「区分」步：候选谓词的筛选本身可以用 choice（哪个问题最能分开这批样本）。
5. 校准：choice 的线是「最大概率下限」与「前二差距下限」两条，score 的线按档位，
   都要从标注数据来。δ 迟滞 choice/score 用 0.15（已测）。
