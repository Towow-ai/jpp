# 总进度：2026-09-22

这份文件回答一个问题：照我们自己的设计文档量，这门语言现在做到哪了。

判据不是测试数。内核有 315 条测试全绿，但测试测的是「写出来的东西对不对」，
不是「设计里该有的东西在不在」。下面这些结论是拿 `05-语言本质-v2.md` 的内核定义
和 `08-最基本的定义-v0.md` 的三个定义性效果，逐条去代码里核出来的。

## 一、内核的五个算子

〔已过期，现状见 地基/黑板/当前.md——过滤（三路 sieve 直接吃题）、配对（pair）、聚合（tally/first_k 给区间）、迭代第二条终止线均已按设计造出，见黑板「阶段3/三路过滤」「阶段3/配对」「阶段3/聚合」「阶段3/迭代第二线」〕

设计说内核是两个类型、一座桥、一道题、三值、五个算子、一本账。
五个算子都是「一组材料进、一组材料出」。逐个核下来是这样。

| 算子 | 设计要的 | 代码里是什么 | 判断 |
|---|---|---|---|
| 过滤 | 吃一组材料和一道题，吐三条流：该做、不该做、拿不准 | `filter(list, fn)` 吃布尔函数，吐一条流 | **名字一样，东西不一样** |
| 配对 | 两组材料两两组合，每对渲染成一个状态 | 一次都没出现 | **没做** |
| 聚合 | 存在 / 全部 / 计数 / 前 k，计数要给区间 | `agg` 是同题多次问取平均或众数 | **名字一样，东西不一样** |
| 迭代 | 两条终止线：步数到顶，或每层材料严格变少 | `loop` 只有步数上限，「键重复即停」做了一半 | 半做 |
| 做 | 对世界执行动作，产出新材料 | `do`，带记账、污染标记、可逆性 | **做对了** |

所以三个问题的答案不是三类，是四类。

设计错了的：没有。设计本身自洽，配对那一格还被实测过（74 段筛成 35 段、配出 595 对、
20 秒、$0.014，见 E8）。

做完了在用的：「做」这个算子，和账本。账本实测过重放，同一程序三次真机键逐条相同。

设计了没做完的：配对整个没有，迭代缺第二条终止线。

**做成了别的东西但名字一样的：过滤和聚合。** 这一类原本不在我预期里，而它比「没做」更麻烦，
因为从名字上看这两格是绿的，不会有人去查。

### 这一条解释了一个具体的坑

同一份材料问十四个问题，两种写法的调用次数差十四倍：

```
map(题组, 查)              → 1 次调用
map(题组, fn(q) { 查(q) })  → 14 次调用
```

结果完全一样，静态检查两边都报 0 警告。

原因就在过滤算子这一格。代码里的 `map` / `filter` 吃的是闭包，所以有闭包可以多包一层；
如果它们像设计说的那样吃的是**一道题**，根本没有闭包可包，融合是结构上自然成立的，
不需要靠一个 pass 去认语法形状。

**这个十四倍不是性能 bug，是过滤算子被做成列表操作的症状。**

〔已过期，现状见 地基/黑板/当前.md——步 13b 合入后，向量化穿过用户函数包装，`map(题组, fn(q) { 查(q) })` 这类被包一层闭包的写法已与 `map(题组, 查)` 同样融合成 1 次调用（sieve-batch-old 14→1、question-forms 10→2），两种写法不再相差十四倍，见黑板「工程/步13b」；过滤算子本身是否仍按「吃闭包」的形状实现（本节诊断的架构原因）未见黑板条目专门核实，这部分判断可能仍成立，需另核〕

## 三、三个定义性效果

`08` 说只有三样效果非语言不可：自指、全局保证、全局优化。

〔已过期，现状见 地基/黑板/当前.md——「题成为一等值」已完成，题式 form/fill、题字段可读且静态核对（E-field），题可计算出新题，见黑板「阶段1/题成为一等值」；二阶出题 `derive` 状态未见黑板条目，可能仍未实现，需另核〕

**自指没做。** 设计原文要求「判断的输出、问题、程序本身都能被判断、被生成、被执行，
这要求它们是同一种一等值」。今天 `Question` 是不透明的，连题面都读不出来（`q.text`
通过静态检查，运行期才报「Question 没有字段 text」）。二阶出题（`derive`）零实现。

**全局保证做了，是目前最结实的一块。** 十八条检查规则落地十七条。未决必须被消费，
`otherwise` 兜不住它。账本可重放。

**全局优化半做。** 上面那个十四倍就是它。`layers` 输出是 `null`。九个 pass 里
管规划的四个（裂变 / 下沉 / 调度 / 预算）全是关的。

〔已过期，现状见 地基/黑板/当前.md——十四倍已由步 13b 向量化修复（见本节上方标记与黑板「工程/步13b」）；规划/推测/提升/向量化分析已从运行时搬出并建成独立 `jpp-plan`（步 13a，黑板「工程/步13a」），`layers`/裂变/下沉/调度/预算四个 pass 现状是否仍全关未见黑板条目逐项核实，需另核〕

## 四、缝

「缝」指的是程序和程序之间、判断和判断之间那些必须有人决定、而库决定不了的事。
原先列了六条，采样之后加到八条。

批调度、深度与终止、弃权的去向、预算、缓存与增量、校准，这六条是原有的。
新增两条：判断力本身不在的时候怎么办，以及时延预算。

弃权那条我们最强。三态出口、必须被消费、四条合法去向，是采样里见到的唯一一个统一形状。
校准那条我们其次，数学那一半（保形认证、覆盖率、证书）实测过，但进料那一半断着。
批调度、深度、缓存、预算四条都在三成上下。判断力缺席那条我们是零。

〔已过期，现状见 地基/黑板/当前.md——「进料那一半断着」已不成立：真值通道（`jpp calib-import`）已建成，题式级线回退、账本记校准来源、两侧联合认证均已实现并真机验证，见黑板「阶段3/真值通道」；批调度已由步13b向量化大幅推进（见本文一节标记）、深度已由步17a/17c结构通道与值级来源建成（黑板「工程/步17a」「工程/步17c」）、预算与缓存也有大量后续构造（步7/7b/7c账本改版、B93预算停机降级、B29夹具线等），「批调度、深度、缓存、预算四条都在三成上下」这句量化估计已严重过期，无对应新数字，具体现状见黑板各「工程/」「阶段3/」条目〕

〔已过期，现状见 地基/黑板/当前.md——判断力缺席已由 B32 造出：重试、退避、escalate/conservative/fail、熔断与时延预算均已实现，见黑板「阶段3/规则-B32」，不再是零〕

## 五、采样带回来的

2026-09-22 采了一天外部材料：官方文档与 22 篇 cookbook、两个官方 SDK 源码、
社区 35 个具名 pattern、约 150 个真实仓库（其中深挖 57 个）、jevable 194 个项目
（找到源码 20 个仓库）、26 篇社区实测文。原始件在 `实测/jpp-采样/`，
195 份 4.7MB，124 份分析。结论写在 `15-采样结论-登记表提议-v1.md`。

采出来的核心是：**所有人都在手写同样的九样东西，一遍一遍，跨语言、互不知晓。**
比如「判断力不在时怎么办」有七份独立实现、五种语言、同一个形状；「多信号合成取最坏」
六份；「确定性手段先削减形状，模型只做窄判断」八份以上。

把这九样放回我们的五个算子和三值桥上，**七样在设计里已经有位置了**。
取最坏就是设计里「存在等于取最大、全称等于取最小」；三四态枚举就是三值加桥；
三重熔断就是迭代的两条终止线加一条判断线。

**别人手写的东西，我们的设计早就给了位置，是实现没跟上。**
九样里只有一样在设计里完全没有位置：判断力本身不在的时候怎么办。

采样也量到一个反面的数：57 个生产样本里，只有 1 个把判断当纯函数缓存。
判断是纯的、可重放的，这是白捡的钱，56 个人没捡。

## 六、已知的具体缺陷，可以直接动手的

**效应标注死锁。** 函数体里有 `transform` 的，不能写显式效应标注。写上 `!{judge, transform}`
被拒（「`transform` 不是效应形式，不写进标注」，`check.rs:278`），不写也被拒
（「标注少了 transform，修法：写成 `!{judge, transform}`」，`check.rs:1559`）。
两条报错互相指着对方。唯一绕法是整个不写标注。315 条测试全绿，因为五个示例里
没有一个在带 `transform` 的函数上写标注。

〔已过期，现状见 地基/黑板/当前.md——死锁已解除：效应表补丁（B0108，`工程/效应表补丁`）给 `transform` 记 `EffectSpec.in_effect_row: false`，检查器改按 `in_effect_row` 算「概念上的效应」（`jpp-check/src/analysis/effects.rs`），`transform` 不再进 `row.concrete`，因而不会被判「标注少了 transform」；两条互相指对方的报错已消失，具体见 地基/rust-jpp/crates/jpp-effects/src/kinds/transform.rs 与 jpp-check/src/analysis/walk.rs〕

**静态检查不认得 `Question` 的字段。** `q.text` 通过 `check`，运行期才炸。
在一个十四题的程序里，这意味着材料已经发出去了才知道写错。

〔已过期，现状见 地基/黑板/当前.md——题字段已可读且静态核对（E-field），见黑板「阶段1/题成为一等值」，此条不再成立〕

〔已过期，现状见 地基/黑板/当前.md——真值通道已建成（`jpp calib-import`），题式级线回退、账本记校准来源、两侧联合认证均已实现并真机验证，见黑板「阶段3/真值通道」；CLI 真机路径已接通（`--backend live`），见黑板「阶段2/真实JEV接线」。注意语义题式的模型标注仍需人工抽检达门槛才转正，未过门槛的记录仍停在待真值，这部分限制仍成立，见黑板「发现/语义题式校准」〕

**真值通道不存在。** `interp.rs:1478` 运行期把样本的 `label` 写死 `None`，
注释自陈「真值通道是未定的另一样」。全仓 `label: Some` 只出现在测试夹具里。
后果是 `commission` 在真实路径上永远拒绝（「没有带标注的样本」），
校准线拿不到运行期证据。

**CLI 没有真机路径。** `jpp run` 走固定观察，帮助文本原话 "no model API requests are made"。
所以写 `.jpp` 的人不能让程序真的问一次 Jev，能产出的校准线都是从自己写的夹具折回来的。

**前端不认 `budget.unsure`。** core 里这个字段在，J-10 的静态检查靠它，`.jpp` 写不出来。

〔已过期，现状见 地基/黑板/当前.md——`.jpp` 现在写得出：`jpp-syntax/src/lower/budget.rs` 已识别 `budget{unsure: …}` 字段并降级，此条不再成立〕

**`match` 不在文法里。** 而 J-05 的条文写着「字面 match 穷尽 warn」，`12` 把 match
列为刷新点。规范引用了语言没有的构造。

## 七、下一步的顺序，以及为什么是这个顺序

〔已过期，现状见 地基/黑板/当前.md——本节列的四步（摆平过滤/聚合、补配对、四个骨架、校准进料）均已完成或大幅推进：过滤/聚合/配对/迭代第二线均已造出（黑板「阶段3/三路过滤」「阶段3/配对」「阶段3/聚合」「阶段3/迭代第二线」）；校准进料（真值通道、两侧联合认证）已建成并真机验证（黑板「阶段3/真值通道」）；四骨架仍未并入主线但已有独立分支原型（黑板「阶段1.5/骨架原型」）。施工顺序现由 地基/17-总规划-v1.md 与 地基/21-工程方案-v1.md 的步骤表统一管理，不再按本节排序，具体在建/已完成步骤见黑板「工程/」各条目〕

**先把过滤和聚合摆平。** 它们现在装的是列表操作和读数平均，而名字让人以为内核那两格
做完了。摆平之后五个算子才是设计说的那五个。顺带那个十四倍会从「靠 pass 认语法」
变成「结构上不可能写错」。

**然后补配对。** 五个算子里唯一整个没有的。设计实测过它，有数。

**然后四个骨架。** 前三件做完，骨架才有东西可搭。骨架是标准库，也是「换任务只改最外层
问题和料库来源」这条验收判据的载体。

**校准的进料那一半单独排。** 真值通道和真机 client 是一件事的两半：没有真机就没有真读数，
没有真值就没有线。这一件不做，校准那条缝的数学一半再结实也用不上。

判断力缺席那一格便宜，七份外部实现形状一致，可以随手加。
时延预算也便宜，`budget` 加一格。这两件不用排队。
