# 手写基线任务书 · 通用部分

每个项目另有一份 `probes/<项目>/baseline/任务书.md`，写该项目要做什么。本页写所有项目共用的规则。
规程依据：`地基/附注/2026-09-24-评估①裁定.md` §六·3「基线规程」。

## 你要做的

用 Python（3.9 可运行，只用标准库）写一个程序，完成项目任务书描述的功能。按你在真实项目里写这个功能的方式写，
不要为了行数刻意压缩或展开，也不需要写注释来凑说明。只实现任务书要求的东西。

- 文件：`probes/<项目>/baseline/<项目名>_a.py`（文件名见项目任务书）。
- 输入：从同目录的 `materials.json` 读材料与阈值（运行时当前目录就是 `baseline/`）。
- 输出：把结果以 JSON 打印到标准输出（`json.dumps(result, ensure_ascii=False)`），不打印别的。
- 判断：只通过判断接口 `jev_interface.judge` 取读数（见下）。不要自己读夹具文件。

## 判断接口

`probes/_baseline/jev_interface.py`，模块文档字符串里写了用法。验收时它从固定观察文件里取读数；
`import jev_interface` 能直接用（验收命令把它所在目录放进了 `PYTHONPATH`）。

    from jev_interface import judge
    answers = judge(material, [question, ...], over=None)

- `material` 是一份材料（字符串或 JSON 对象），项目任务书规定每道题的材料具体是什么形状，**必须照写**，
  否则取不到读数（接口会报 `LookupError`，说明哪道题、哪份材料查不到）。
- 题：`{"type": "noul", "instructions": 题面}`（是非题，答案 `{"noul": p}`，p 是「是」的概率）；
  `{"type": "choice", "instructions": 题面}` 配 `over=[候选…]`（K 选一，答案 `{"probabilities": {"c0": p0, …}}`，
  测过候选顺序置换时另有 `"mode_share"`：1.0 表示换序后答案不变）；
  `{"type": "score", "instructions": 题面, "criteria": [档位文字…]}`（打分，答案 `{"probabilities": {"0": p0, …}}`）。
- 同一份材料上的多道题可以一次调用问完，也可以分开问，读数相同。

## 阈值规则（所有项目通用）

`materials.json` 的 `thresholds` 给每道题一条记录 `{hi, lo, delta}`：
- 是非题：`p >= hi + delta` 为「是」；`p <= lo - delta` 为「否」；否则为「未决」。
- K 选一：取概率最大的候选（并列取靠前的）；只有答案里 `mode_share` 存在且等于 1.0、并且最大概率 `>= hi + delta` 时才算选中，否则「未决」。
- 打分：取概率最大的档位（并列取靠前的）；最大概率 `>= hi + delta` 时取该档，否则「未决」。

## 验收

在 `地基/rust-jpp` 目录下运行：

    python3 scripts/measure_expr.py --check <项目>

它以固定观察跑你的程序，把输出与期望结果逐项比较，打印「通过」或第一处不同。输出里可以有任务书没要求的键，
不影响验收。通过即完成。

## (a) 账本与重放

- 程序接受命令行参数 `--ledger-out <文件>`：每份材料的一次判断请求完成后，向该文件追加一行 JSON
  `{"material": 材料, "questions": [题…], "over": 候选或 null, "answers": [答案…]}`，用 `json.dumps(…, sort_keys=True, ensure_ascii=False)` 序列化。
  （`judge_batch` 提交的多份材料各写一行。）
- 程序接受 `--replay <文件>`：**不发任何判断调用**，按 `(material, questions, over)` 从文件取答案（比较时三者都用
  `json.dumps(…, sort_keys=True, ensure_ascii=False)` 的结果）；取不到时以非零退出码停止，并在标准错误写明是哪道题、哪份材料。
- 两个参数都不给时行为同 T0。
- 验收：① 固定观察下带 `--ledger-out` 运行，输出与期望相同；② 带 `--replay <①的文件>` 运行，判断调用数为 0，且标准输出与 ① 逐字节相同；
  ③ 删去账本任一行再 `--replay`，退出码非零。

## (b) 预算停机

- 程序接受 `--max-calls N`。已发出的调用（按 `calls()` 的口径：一份材料的一次请求计一次）达到 N 后不再发新调用。
- **发出顺序**：一层一层发；同一层内按项目任务书规定的顺序发（`judge_batch` 的请求也按这个顺序排列）。
  于是预算在哪里用完是确定的：排在前面的先问到，后面的问不到。
- 本该判断而没有判断的项（没问到的那份材料上的题）按项目任务书写的形式列进输出字段 `unobserved`。
  问不到的项**不算任何回答**：不进「是」「否」「未决」的任何列表或计数；依赖它的后续层的题也不问（这些后续项不再列）。
- 输出的其余字段按已问到的读数照常计算，仍是合法 JSON，退出码 0。
- 不给 `--max-calls` 时不设上限；`unobserved` 照样输出（为空）。
- 验收：① 以项目任务书给定的 N 运行，`calls() == N`，输出等于项目任务书写的预算停机期望（`unobserved` 与其余字段都比）；
  ② N = 1000（大于总调用数）时输出与不设上限相同、`unobserved` 为空。

## (c) 合批与同层一起发

- 同一份材料上、同一层里要问的多道题必须在**同一次调用**里问完（`judge(material, [q1, q2, …])`）。
- 同一层内的多份材料必须用**一次** `judge_batch` 提交：

      from jev_interface import judge_batch
      results = judge_batch([(material1, [q, …], over1), (material2, [q, …]), …])
      # results[i] 是第 i 份请求的答案列表，与该请求的 questions 同序

  一次 `judge_batch` 计 `len(requests)` 次调用、**1 轮**（`rounds()`）；一次 `judge` 计 1 次调用、1 轮。
- 「层」：一道题要等另一道题的答案才能决定问不问、问什么，它就在后一层。项目任务书写明每个项目的层怎么分、调用上限与轮数上限。
- 调用上限按「每层每份材料至多一次」算：上限 = 各层要问的材料数之和。
- 验收：① `calls()` ≤ 项目任务书写的调用上限；② `rounds()` ≤ 项目任务书写的轮数上限。

## (d) 认证线

`materials.json` 不再给阈值。阈值（下称「线」）要由程序在发出任何判断之前，从 `labels.jsonl` 里带真值的标注算出来；
不许手写，也不许写死在程序里。每行 `{"key", "item", "p", "label", "source"}`；K 选一与打分的行另有
`"op"`（`"select"` 或 `"measure"`）与 `"pick"`。

**样本。** 按 `key` 分组。是非题（没有 `op`，或 `op` 为 `"test"`）：样本是 `(p, label)`，`label` 为 `true`/`false`。
K 选一与打分：样本是 `(p, pick == label)`，`p` 是最大候选概率，`pick` 是读数的最大候选下标，`label` 是真值下标。

**线怎么用。** 一条线 `{hi, lo}` 按 T0 的「阈值规则」使用，δ 取 `materials.json` 的 `deltas[键]`：
是非题 `p >= hi + δ` 判「是」，`p <= lo − δ` 判「否」；K 选一与打分 `p >= hi + δ` 才选中（`lo` 写 0）。
某一侧的**已决行**是被这条线判进该侧的标注行；其中的**错误**：「是」侧是真值为否的行，「否」侧是真值为是的行，
K 选一与打分是 `pick != label` 的行。

**线要满足的性质。** 对每个键的每一侧（是非题两侧，K 选一与打分只有上侧），这条线在**同分布、程序没见过的新标注**上要做到：
- 该侧已决行数 n ≥ 22；
- 已决行里的错误个数 k 使 Clopper–Pearson 单侧上界 U(k, n) ≤ α，其中 α = 0.1、置信参数 c = 0.1
  （U(k, n) 是使 `P(Bin(n, U) ≤ k) = c` 的错误率；k ≥ n 或 n = 0 时为 1）；
- 是非题 `lo <= hi`。

怎样从 `labels.jsonl` 算出满足这个性质的线由你定（留出一部分标注做检验、固定序检验、零错误计数都可以），
在程序里用注释写明你用的方法。只为本项目 `labels.jsonl` 里出现的题型写代码。
一个数学事实：一侧零错误时，已决 22 行即满足上界（U(0, 22) ≈ 0.0994）。

某个键算不出满足性质的线（例如样本不够），该键「待真值」。
**任一键「待真值」时程序不发任何判断调用**，输出 `{"status": "待真值", "key": <待真值的键里按键名排序的第一个>}`，退出码 0。

- 程序接受 `--print-lines`：只算线，把 `{键: {"hi": …, "lo": …}}`（待真值的键写 `{"status": "待真值"}`）以 JSON 打到标准输出后退出，不发判断调用。
- 验收：① 考官另持一份你看不到的标注（同一生成方式、另一批样本），用 `--print-lines` 给出的线在上面逐键逐侧核
  n ≥ 22、U(k, n) ≤ α 与 `lo <= hi`（比较留 1e-9 容差）；② 把按键名排第一的键截到 8 行，程序输出 `待真值`，不发调用；
  ③ 线算出后，功能验收照常通过（本项目的标注保证任何满足上述性质的线在固定观察的读数上给出与 T0 阈值相同的出口，
  所以 T1 的功能期望与 T0 相同）。

## 四项一起时

`--ledger-out`、`--replay`、`--max-calls`、`--print-lines` 可以同时给；`--replay` 下读数来自账本、不计调用。
